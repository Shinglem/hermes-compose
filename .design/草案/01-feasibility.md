## 3. 三个不可平移的硬点

1. **前端插件体系是 JS/TS + React**
   插件贡献项是 `render?: () => ReactNode` —— 要在非 React 栈里渲染，必须自带 React 运行时 + DOM，
   等于自造 WebView。保留 UI 插件的务实路径只有内嵌浏览器。
   区分：`data?: unknown` 那类（主题 / 布局预设 / 命令）是纯数据，可跨语言解析。
   *本项目决策：放弃 UI 插件（见 ADR-003）。*
2. **xterm.js 终端**（PTY + WebGL + 多 addon）：Kotlin 侧无等价物，但有替代路径（BossTerm / pty4j）。
3. **流式 Markdown / 代码高亮 / 数学 / 编辑器栈**：JS 生态最厚、Kotlin 侧最空。

**降本的最大杠杆不是"少写代码"，是"改架构定义"**：终端与编辑器改走原生库之后，
"WebView 兜重资产"这个 B 档定义本身就不再成立，真实形态变成"原生为主 + 1 个 WebView 小岛"。

## 4. 本项目口径的成本（范围已裁剪）

已确定的范围与估算（人天，单人）：

| 模块 | 人天 | 依据 |
|---|---:|---|
| 数据层（WS JSON-RPC + REST + 连接管理 + 契约生成） | 26 | 见 `03-architecture.md` |
| 渲染栈（Markdown 接入 + 流式对接 + 工具卡片 + 复制/引用） | 32 | 基于 `multiplatform-markdown-renderer` |
| 输入框 composer（chip / @ 补全 / 粘贴 / 历史） | 16 | `BasicTextField` 路线 |
| 布局与主窗口（Scaffold + rail + 会话列表 + 能力模式） | 18.5 | 见 `04-ui-spec.md` |
| 终端（BossTerm 接入 + 折叠面板） | 6 | 含 PTY resize、配色、快捷键 |
| 设置页（模型 / 外链编辑器 / 代理 / 外观） | 4 | 复用能力页骨架 |
| 打包与自动更新 | 5 | MSI 打包 + 简单更新检查 |
| **合计** | **≈ 108 人天** | **≈ 5 人月（单人）** |

对比：完整对等的 B 档为 13–18 人年。**差距来自范围裁剪，不是技术提升** ——
砍掉的是：前端插件生态、文件浏览与编辑器、远程屏幕、群聊/Bot Mode、多语言、视觉复刻。

### 这个数字的可信度

- 数据层与渲染栈是**最容易低估**的两块（协议非标准、渲染保真度难）。
- 上表未含：调试返工、spike 验证（约 10 人天）、UI 打磨。
- 建议按 **+30% 缓冲**理解为 ≈ 7 人月，对应 MVP 档的 0.5–1 人年上界附近。

## 5. 结论

1. **可行**，且不需要 WebView 兜底（除未来的 mermaid / HTML 预览）。
2. 原版最贵的两个字是"对等"与"生态"；本项目两个都不要，成本因此下降一个数量级。
3. 真正的风险不在工作量，而在**三处保真度**：
   - 流式渲染的手感（抖动 / 重排）
   - 中文输入法（IME 组合态）
   - 终端与 Swing/Compose 互操作的细节
   这三处都要在 P0/P1 阶段就验，不能留到最后。
