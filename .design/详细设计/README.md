## 写作规则（本篇的）

1. **可执行**：结论要能被照着写代码 —— 给出包路径、文件名、类名、方法签名、字段名。
2. **不重复草案**：选型理由、范围、验收口径一律链接，不复述。
3. **不重复 `AGENTS.md`**：硬约束只引用编号。
4. **版本给来源**：写版本号必须同时写核对时间与数据源。
5. **坑写三件事**：现象 / 原因 / 应对。
6. **未验证的结论要标明**：写"未验 + 原因"，不要写"应该没问题"。
7. **计划执行完就归档**：别让已完成的计划冒充现状。
