# 00 · 功能域总览

> 本篇是**功能设计的主干**：划清 7 个功能域的边界、各自的状态与数据源、跨域约定与关键时序。
> 每篇域级设计（`功能/01-…` 起）再展开到"组件树 + 状态字段 + 方法签名 + 空/错/载入态"。

## 1. 功能域划分

约定：**一个功能域 = 一个 `feature/<域>` 包 = 一个状态持有者 + 一个 Repository（需要数据时）**。

| # | 域 | 职责 | 不负责 |
|---|---|---|---|
| 1 | `shell` | 窗口骨架、模式切换（会话/能力）、profile rail、状态条、全局横幅与 Snackbar | 任何业务数据 |
| 2 | `session` | 会话列表：分组、置顶、搜索、重命名、删除、新建 | 消息内容 |
| 3 | `chat` | 当前会话的消息列表、流式渲染、工具卡片、审批卡片、消息级操作 | 输入与发送 |
| 4 | `composer` | 输入框、chip、@ 补全、粘贴/拖入、草稿、发送 | 消息展示 |
| 5 | `terminal` | 终端面板展开/收起、PTY 生命周期、焦点规则 | 会话逻辑 |
| 6 | `capabilities` | 技能与工具 / 消息平台 / 定时任务 三页 | 聊天 |
| 7 | `settings` | 模型、外链编辑器、代理、外观、日志入口 | 其余 |

依赖方向：`shell` → 各域；`composer` → `chat`（提交后进入流式）；`chat` ← `session`（选中会话 id）；
`capabilities` / `settings` 独立。**域之间不互相持有状态对象**，只通过 `shell` 或 `AppContainer` 传 id 与回调。

## 2. 各域速览

### 2.1 `shell` — 应用骨架

| 项 | 内容 |
|---|---|
| 可见元素 | 左 rail（profile + 模式切换按钮）、`Scaffold`、底部状态条（28dp）、顶部连接横幅、Snackbar 宿主 |
| 状态 | `ShellState(mode: ShellMode, activeProfile: ProfileId, connection: ConnectionState, windowSizeClass)` |
| 数据源 | `profiles.list`（WS）、本地偏好 `ui.mode`、连接状态来自 `GatewayClient` |
| 关键交互 | 切 profile、切模式、点状态条模型切换、`Ctrl+B` 折叠中栏、`Ctrl+,` 打开设置 |
| 空/错/载入 | 未连接 → 黄色横幅 + 重试；启动失败 → 整页诊断（`04-ui-spec` §8） |
| 验收 | L1–L5（`05-acceptance.md` §4）、D1（断线恢复） |

### 2.2 `session` — 会话列表

| 项 | 内容 |
|---|---|
| 可见元素 | 搜索框、置顶区、时间分组（今天/昨天/7 天内/更早）、行（标题+时间+未读点+`⋯`）、底部"新建会话" |
| 状态 | `SessionListState(query, pinned, groups, selectedId, collapsedGroups, load: Loadable<List<SessionSummary>>)` |
| 数据源 | `session.list`、`session.create` / `.delete` / `.title` / `.archive`；偏好 `sessions.pinned`、`groups.collapsed`、`drafts.<id>` 是否存在 |
| 关键交互 | 搜索过滤（本地）、置顶/取消、重命名、删除（确认对话框）、折叠分组、`Ctrl+N` / `Ctrl+K` |
| 空/错/载入 | 空 → 空状态 + 新建；载入 → 3–5 条骨架行；失败 → 横幅 + 保留缓存 |
| 验收 | S1–S8（§3）、L2 |

### 2.3 `chat` — 消息与流式

| 项 | 内容 |
|---|---|
| 可见元素 | 顶栏（标题/模型/`⋯`）、消息列表、工具调用卡片、审批卡片、消息操作条（复制整条/引用）、吸底按钮 |
| 状态 | `ChatState(sessionId, messages: List<MessageVm>, streaming: StreamingState?, scroll: ScrollState, load: Loadable<Unit>)` |
| 数据源 | `session.history`（首屏）、事件流（增量/完成/工具/用量）、`session.interrupt`（停止）、`session.usage` |
| 关键交互 | 滚动（吸底 + 上滚暂停）、复制整条、引用到 composer、代码块复制、展开工具参数、审批 allow/deny |
| 空/错/载入 | 未选中 → 右侧空态；历史失败 → 横幅 + 重试；流式中断 → 消息尾部标"已停止" |
| 验收 | R1–R8（§2）、C1–C10（§3 部分）、D6（重复投递幂等） |

### 2.4 `composer` — 输入

| 项 | 内容 |
|---|---|
| 可见元素 | `BasicTextField` 多行区、chip 行（@ 文件/技能）、附件按钮、粘贴图片、发送按钮、快捷键提示 |
| 状态 | `ComposerState(text: TextFieldValue, chips: List<Chip>, attachments: List<Attachment>, sending: Boolean, history: RingBuffer<String>)` |
| 数据源 | `prompt.submit`（1800s ack）、`drafts.<sessionId>` 偏好、剪贴板与文件拖入（平台层） |
| 关键交互 | Enter 发送 / Shift+Enter 换行、@ 补全浮层（键盘导航）、上下键取历史、粘贴图片、`引用` 注入 |
| 空/错/载入 | 发送中禁用重复提交（但允许继续输入）；ack 超时 → Snackbar + 保留草稿 |
| 验收 | C1–C10（§3）、R8 |

### 2.5 `terminal` — 终端

| 项 | 内容 |
|---|---|
| 可见元素 | 收起条（32dp：`终端` + 状态点 + 进程数 + 新建/展开按钮）、展开面板（占右栏 40%，可拖拽 20%–70%）、左侧标签 rail |
| 状态 | `TerminalPanelState(layout(expanded, heightFraction, activeTabId, tabs), running)`；`TerminalViewModel` 挂在 `AppContainer`（全局，不属于会话） |
| 数据源 | `:modules:terminal`（宿主）+ `:modules:terminal-bossterm`（BossTerm 裁剪 fork，Compose 原生渲染）；PTY 由 BossTerm 内部的 pty4j 起；cwd 在**建标签时**快照一次 |
| 契约 | server→client `terminal.read`（合成 `{total_lines,start,end,viewport_rows,cursor_row,text}`）、client→server `terminal.resize`、事件 `agent.terminal.output` / `terminal.close` |
| 关键交互 | `Ctrl+`` 开关、拖拽高度、多标签（切标签不杀进程）、点入后键盘归终端（`Ctrl+C`/`Ctrl+W`/`Tab`）、切模式时隐藏、切回恢复 |
| 空/错/载入 | PTY 启动失败 → 条内红点 + 日志；不可用平台 → 隐藏入口 |
| 验收 | T1–T14（§5 + 新增） |

> 详见 ADR-041（全局多标签、进程不复活）与 ADR-054（改用 Compose 原生渲染）。域级设计见 [`04-终端.md`](04-终端.md)。

### 2.6 `capabilities` — 能力三页

| 项 | 内容 |
|---|---|
| 可见元素 | 中栏固定三项；右栏分别为技能与工具（搜索 + 分段 技能/工具集/**发现** + Switch + 展开 SKILL.md）、消息平台（卡片 + 状态 chip + 表单）、定时任务（列表 + cron + 下次/上次 + Switch + 编辑） |
| 状态 | `CapabilityState(section, skills: Loadable<List<SkillVm>>, catalog: Loadable<List<SkillCatalogEntry>>, toolsets: …, platforms: …, cron: …, editing: CronDraft?)` |
| 数据源 | REST：`/api/skills`、`/api/skills/toggle`、`/api/skills/hub/official`（可选技能库，本地扫描）、`/api/skills/hub/install`、`/api/tools/toolsets`、`/api/messaging/platforms`、`/api/cron/jobs`、`/api/cron/blueprints`、`/api/cron/delivery-targets`；写操作后**回读校验** |
| 关键交互 | 搜索、切换开关（乐观更新 + 失败回滚）、展开详情、保存表单、测试连接、`立即运行` cron |
| 空/错/载入 | 每页独立 `Loadable`；保存失败 → Snackbar + 恢复原值；**首屏要等连接就绪再拉**（本地后端 ready 前发的请求一定是假失败） |
| 发现页边界 | 只用 `/api/skills/hub/official`（152 项，0.6s，离线可用）。`hub/sources`、`hub/search`、`hub/preview` 走后端联网，本机实测 40s+ 超时；官方桌面端的「发现 276」是前端直连 `nousresearch.github.io/.../skills.json`（64 MB，直连不可达），v0.2.0 都不做 |
| 验收 | A1–A6（§6） |

### 2.7 `settings` — 设置

设置页有**两个数据面**，不要混：

| 面 | 内容 | 来源 | 生效 |
|---|---|---|---|
| 应用设置（**已实现**） | 后端模式与路径、日志、窗口、界面与网络超时 | 本地 `config.json` / `options.json`（+ `*_custom.json` 覆盖层） | 写 `_custom`；`options.*` 立即生效，其余重启生效 |
| 终端设置（**已实现**） | 字体族、字号、滚动回看行数、前景/背景色 | 本地 `config/state.json` 的 `ui.terminalSettings` | **新开的终端标签生效**（字体在 `TerminalPanel` 构造时确定，改已有会重建 PTY） |
| 提供方密钥（**已实现**） | 按 provider 分组填 API key / base URL | REST `GET /api/env`（读） / `PUT /api/env`（写 `HERMES_HOME/.env`） | **立即生效**（新会话使用）；明文只在输入框里，客户端不缓存 |
| 配置档案（**已实现**） | 档案列表 / SOUL.md 编辑 / 新建（可克隆）/ 重命名 / 删除 / 导入导出 | REST `GET /api/profiles`、`GET|PUT /api/profiles/{name}/soul`、`POST /api/profiles`、`PATCH`、`DELETE`、`POST .../export`、`POST /api/profiles/import`（**收归档路径**，不是字节流） | 后端 `~/.hermes/profiles/<id>/`；写后一律回读列表 |
| 模型（**主模型 + 辅助模型已实现**） | profile 默认模型、上下文长度覆盖、辅助任务槽位 | `GET /api/model/info`、RPC `model.options`（目录）、`POST /api/model/set`（`scope=main` / `auxiliary` + `task`，`task=__reset__` 全重置）、`PUT /api/config`（稀疏 diff，只写 `{model:{context_length}}`） | 后端 config.yaml；**对新会话生效**（当前会话走 RPC `config.set`，是另一条路） |
| 安全（**三页已实现**） | 审批（模式/超时/MCP 重载确认/命令白名单）、隐私与网络（日志脱敏/内网访问）、检查点 | `GET /api/config` + `PUT /api/config`（**稀疏 diff**，只提交改动过的字段，非法枚举/数字不发） | 后端立即生效；`approvals.mode` 热广播给运行中会话，`checkpoints.enabled` 对新会话 |

应用设置的字段目录是唯一事实源（`SettingsCatalog`），页面按字段 `kind` 自动生成控件。
详见 [`../工程与代码/05-打包与配置.md`](../工程与代码/05-打包与配置.md) §3.4.1。

| 项 | 内容 |
|---|---|
| 可见元素 | 左栏**两级**：一级分组（可折叠，`NavSectionHeader`）→ 二级页面（`NavRow`）。当前「选项」下是后端连接 / 应用 / 日志 / 窗口 / 界面与网络，「终端」下是外观，「提供方」下是密钥，「配置档案」下是档案（页内再分列表 + 详情）。**不允许任何入口裸挂在根上** |
| 状态 | `SettingsState(sections, selected: SettingsPage, collapsedSections, values: Map<key, text>, error, saved)`；`dirty` 在 ViewModel 里 |
| 数据源 | 本地文件（`FileSettingsStore`）；表单初值 = 当前生效配置 + 默认值全量快照 |
| 关键交互 | 折叠一级分组（落 `state.json` 的 `ui.settingsCollapsed`）、选二级页面、按 kind 渲染控件（Switch / FilterChip / 输入框）、保存只写改过的键、校验失败就地报错 |
| 布局 | 与「会话」「能力」共用 `AdaptiveListDetail` —— 中栏底色、选中块、窄窗单栏退化三处由此统一（此前设置页自绘 Row + `surfaceContainerLow`，底色与另两页不一致） |
| 空/错/载入 | 保存失败 → 显示原因、不静默；后端设置那面留 P6 |
| 验收 | 只写 `_custom`；未改动不落盘；`options.*` 保存后立即生效（主题当场切换已验证） |

## 3. 跨域约定

### 3.1 profile 是全局上下文

- `activeProfile` 只在 `shell` 里改；改动即触发：`session` 重新取列表（**保留已有缓存**）、
  `capabilities` 作废重取、`chat` 记住 `(profile, sessionId)` 以便切回恢复（03-architecture §4.2）。
- 事件订阅按 `profile` 过滤，**不得**把别的 profile 的事件写进当前 UI。

### 3.2 连接状态只有一个

- 状态源：`GatewayClient.connection: StateFlow<ConnectionState>`。
- `shell` 负责呈现（横幅 / 状态条 / 重连次数）；其他域**只读**，不各自弹提示。
- 断线期间：已渲染内容保持、发送入口禁用并提示"等待恢复连接"，草稿不丢。

### 3.3 事件必须幂等

- 事件去重键：`(sessionId, messageId, seq)`；重放事件（`replayed = true`）不再触发打字动画与提示音。
- 同一 `messageId` 的 delta 重复到达 → 覆盖而非追加。

### 3.4 草稿按会话隔离

- `drafts.<sessionId>` 存 Markdown 原文 + chip 列表；切会话时保存/恢复；发送成功后清除。
- 草稿写盘做 500ms 防抖，避免每次按键写偏好。

### 3.5 流式合并

- 事件到达 → `Channel`；每 16–32ms 合并一次追加；合并只在 UI 层做，Repository 保留完整文本。
- 一轮结束（完成事件）时强制 flush 并落一次草稿/历史缓存。

## 4. 关键时序

### 4.1 启动

```
main() → DesktopContainer.build()（创建 GatewayClient/RestClient/Repos，不连接）
  → Window → AppShell
  → LaunchedEffect: container.start()
       ├─ GET /api/status（10s）        → 不可用：整页诊断
       ├─ WS connect
       └─ 并发批量读（60s）：profiles.list / config / model.info / cron.jobs
  → session.list → 渲染列表（骨架 → 内容）
```

### 4.2 发送一条消息

```
Composer.submit
  → 本地插入 user 消息（optimistic，id 用 pending-<uuid>）
  → prompt.submit（ack 超时 1800s，不阻塞 UI）
       ├─ ack 成功 → 用服务端 messageId 替换 pending id
       └─ ack 失败 → 消息标红 + Snackbar + 草稿恢复
  → 事件流：delta 累积（16–32ms 合并）→ 完成事件 → 落定消息、更新用量、刷新会话列表行
  → 期间可 session.interrupt 停止生成
```

### 4.3 断线重连

```
心跳 deadline 超时 → 判定死连接 → 关 socket → 指数退避（1s→30s）
  → 重连成功 → session.events.since(lastEventId)
      → 补齐事件（replayed=true）→ 幂等合并进当前消息
  → UI：横幅显示"重连中（第 N 次）"，恢复后 1.5s 自动收起
```
