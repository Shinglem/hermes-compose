# 01 · 壳与会话列表

> 覆盖 `shell`（窗口骨架、profile rail、状态条、自适应两窗格、全局快捷键）与
> `session`（会话列表：分组、折叠、搜索、新建）。
>
> 依据：[`00-功能域总览.md`](00-功能域总览.md) §2.1–§2.2、[`../../草案/04-ui-spec.md`](../../草案/04-ui-spec.md)、
> 决策：[ADR-037](../../草案/07-decisions.md)（rail 在 scaffold 外）、ADR-038（状态条不显示模型）、
> ADR-044（能力入口不再是开关）。本篇按**已实现行为**写，未实现项在 §1 末尾单列。

---

## 1. 可见行为

| 区域 | 用户能做什么 | 实现 |
|---|---|---|
| 左 rail | 点 profile 头像切档案（切档即回会话模式）；底部「能力」「设置」两个入口 | ✅ |
| 模式切换 | profile → `SESSIONS`、能力 → `CAPABILITIES`、设置 → `SETTINGS`；**设置不落盘**（重启回会话） | ✅ |
| 窄窗 | 宽度 < 960dp 时 rail 只剩图标（隐藏文字标签） | ✅ |
| 状态条 | 连接色点、profile 名、未提权提示、可点的「网关 xx ms」/「服务 xx ms」chip、连接文案、断线重试图标、后端版本 | ✅ |
| 后端详情 | 点状态条 chip → `AlertDialog`：启动失败原因 + 控制台日志尾 + 「重试启动」 | ✅ |
| 会话列表 | 搜索、按时间分组（今天/昨天/7 天内/更早）、点组头折叠、选中高亮、底部「新建会话」 | ✅ |
| 会话行操作 | hover 出现 `⋯` → 重命名 / 置顶 / 复制为新会话 / 导出 JSON / 导出 Markdown / 归档 / 删除；各带对话框或保存框；底部「已归档（N）」可展开恢复 | ✅ |
| 运行态点 | 行首小圆点表示后端有 live 会话（`session.active_list`，5s 轮询；失败静默） | ✅ |
| 内容搜索 | 搜索框右侧按钮切到「搜消息」模式：`GET /api/sessions/search?q=`，结果整块替换列表（与标题过滤不叠加），标题用后端 `title` | ✅ |

全局快捷键：`Ctrl+N` 新建、`Ctrl+,` 设置、`Ctrl+K` 命令面板、
`Ctrl+[` / `Ctrl+]` 上/下一个会话、`` Ctrl+` `` 终端开合、
`Ctrl+Shift+`` ` 终端新标签、`Ctrl+(Shift+)Tab` 终端标签切换。

命令面板（`Ctrl+K`）是**纯本地**入口：已加载会话的标题过滤 + 常用动作（新建 / 设置 / 能力页 /
终端开合 / 复制与导出当前会话 / 子代理面板 / 检查后端更新）。全文检索只在会话侧栏的「搜消息」里，
不要让两个入口抢同一个后端请求。

**未实现（如实记录，勿在文档里假装有）**：

| 缺什么 | 现状 | 接口是否就绪 |
|---|---|---|
| 会话右键菜单 | 只有行内 `⋯` 菜单，无右键 | — |
| 新建时自定义标题 | `createSession` 支持 `title`，UI 未暴露 | 已支持 |
| Snackbar | 两域均未用 `SnackbarHost`，反馈走 `ErrorBanner` / 对话框 | — |
| 会话列表实时刷新 | 已消费后端 `sessions.changed`（400ms 去抖后重拉列表）；新建会话进行中不刷，避免把未落库的那条闪掉 | ✅ |
| 置顶的跨设备一致 | 置顶存**本地偏好** `sessions.pinned`；后端 `pinned` 字段写不进（见 §7） | 后端字段有，fence 协议未吃透 |
| 归档列表的权威来源 | 后端 `session.list` 不返回归档行，所以「已归档」列的是**本地快照**（归档时记下 id/标题）；换机器看不到之前归档的会话 | 后端没有"列归档"接口 |

## 2. 状态字段

```kotlin
// ShellState.kt:30
data class ShellState(
    val mode: ShellMode,                    // SESSIONS / CAPABILITIES / SETTINGS
    val profiles: Loadable<List<ProfileSummary>>,
    val activeProfile: String?,             // null = default
    val connection: ConnectionState,        // Idle/Connecting/Connected/Reconnecting/Disconnected/Closed
    val health: BackendHealth?,             // 状态条版本号来源
    val backendKind: BackendKind,           // LOCAL / REMOTE
    val backend: BackendBootState,          // Idle/Starting(step)/Ready/Failed(message, detail)
    val backendLogs: List<BackendLogLine>,
    val gatewayProbe: ProbeState,           // /api/status 探活（唯一后端：官方 gateway）
)
// 派生：profilesOrEmpty / activeProfileKey / activeProfileLabel / isConnected

// SessionListState.kt:29
data class SessionListState(
    val load: Loadable<List<SessionSummary>>,
    val profile: String?,
    val query: String,
    val collapsedGroups: Set<SessionGroup>,
    val selectedId: String?,
    val justCreatedId: String?,             // 刚建未落库：history 404 属正常，走 adoptEmpty
    val creating: Boolean,
    val createError: AppError?,
    val pinned: Set<String>,                // 本地偏好 sessions.pinned
    val pinnedCollapsed: Boolean,           // 「置顶」分组的折叠（与时间分组分开记）
    val rowBusyId: String?,                 // 重命名 / 删除在途的那一行
    val rename: RenameDraft?,               // 非空 = 重命名对话框打开
    val confirmDeleteId: String?,           // 非空 = 删除确认框打开
    val rowError: AppError?,                // 行级操作失败横幅
    val archived: List<ArchivedSessionRef>, // 归档快照（本地记，后端列表不返回归档行）
    val archivedExpanded: Boolean,
    val confirmArchiveId: String?,
)
```

`SessionRow.Header(group: SessionGroup?, collapsed: Boolean)`：`group == null` 表示「置顶」小分组，
排在所有时间分组之前；置顶项会从时间分组里移除，不会出现两次。

`SessionSummary(id, title, preview, startedAt, messageCount, source)`，显示名 `title ?: preview ?: id`；
分组与时间标签由 `core/time/TimeFormat.kt` 的 `groupOf()` / `labelOf()` 算（纯函数，可单测）。

## 3. 组件树

```
AppShell                      ← 装配全部 ViewModel + 快捷键 + 跨域 LaunchedEffect
├── Row
│   ├── ProfileRail           ← 自绘 Surface + Column（不用 NavigationRail，硬约束 9）
│   └── when (mode)
│       ├── SESSIONS     → AdaptiveListDetail(list = SessionListPane, detail = ChatPane)
│       │                   └── 底部 TerminalPanel（内容由 terminalContent 插槽注入）
│       ├── CAPABILITIES → CapabilitiesWorkspace
│       └── SETTINGS     → SettingsPane
└── bottomBar = StatusBar + BackendDetailDialog（按需）
```

`AdaptiveListDetail` 包 `ListDetailPaneScaffold`：断点 840dp / 1200dp；`key(宽度档位)` 重建 navigator
绕 CMP-8735；单窗格时显示 `DetailBackBar` 返回条。**rail 必须在 scaffold 外面**（ADR-037）。

会话列表行：`SessionGroupHeader`（可点击折叠）+ `SessionRowItem`（标题 + 时间 + 单行预览 + 选中态）。

## 5. 空 / 错 / 载入

| 情形 | 表现 |
|---|---|
| 会话正在加载（无缓存） | 5 条灰色占位行 + 「加载中」 |
| 首次加载失败 | 居中 `ErrorBanner` + 重试 |
| 列表为空 vs 搜索无结果 | 两套 title/body（`EmptyState`），不要混成一句"没有数据" |
| 有缓存但刷新失败 | 顶部 `ErrorBanner` + 保留旧数据（不白屏） |
| 新建失败 | 搜索框下方独立 `ErrorBanner`，关闭即清 `createError` |
| profiles 拉取失败 | rail 沿用旧值渲染，**rail 内无错误提示**（已知缺口） |
| 本地后端未 Ready | 跳过探活（避免刷失败）；`Ready` 后 `gateway.stop(); start()` 强连一次 |
| 连接断开 | 状态条转红 + 重试图标；不阻塞界面 |
| 切 profile 后原 profile 不存在 | 回落 `default` 并写回偏好 + `Log.info` |

## 6. 验收条目

- L1 冷启动到可用：窗口出现 → 后端 Ready → 会话列表有数据，状态条「已连接」。
- L2 左 rail 点 profile：会话列表清空重拉、选中态清空、rail 高亮跟着变；重启后仍是该 profile。
- L3 窄窗（< 960dp）：rail 只剩图标；< 840dp 时右栏变单栏并能用返回条回去。
- L4 断线：拔掉后端 → 状态条「已断开」+ 重试图标；后端回来点重试能恢复。
- L5 快捷键：`Ctrl+N` 建会话、`Ctrl+[`/`Ctrl+]` 在会话间移动、`Ctrl+,` 进设置（设置里也能退出）。
- L6 会话分组折叠：折叠状态在切模式/切 profile 回来后仍保留（本轮运行内）。
- L7 会话行操作：hover 出 `⋯` → 重命名后标题在**回读**（重新拉列表）后仍是新标题；
  置顶后排到「置顶」分组且**重启客户端**还在；删除后行消失、若删的是当前选中项右栏回到空态。
- L7b 归档闭环：归档 → 行消失、底部出现「已归档（N）」→ 展开点「恢复」→ 会话回到时间分组、条目从归档区移除。
- L8 实时刷新：一轮对话结束后后端推 `sessions.changed` → 列表在 400ms 内自动重拉
  （标题自动生成、别的客户端新建/删除都无需手动切换 profile）。

## 7. 坑

| 坑 | 说明 |
|---|---|
| rail 不能放进 `extraPane` | 窄窗 `maxHorizontalPartitions` 变化时 `extraPane` 会被收起，而 rail 是导航（切 profile / 切模式），消失就没法操作 |
| CMP-8735：scaffold 不随 resize 自适应 | 必须把 `PaneScaffoldDirective` 绑到窗口宽度档位并 `key(档位) { ... }`；代价是跨断点会丢导航栈 |
| 分组标题不能用 `stickyHeader` | 与 `VerticalScrollbar` 组合有已知闪烁（CMP #3016），用普通标题行 |
| `ListDetailPaneScaffold` 里的两栏底色由组件统一 | 自绘 `Row + background(...)` 会让设置页中栏与会话列表中栏底色不一致，见 ADR-047 |
| `justCreatedId` 的 history 404 不是错误 | 后端还没落库，chat 走 `adoptEmpty()`，不要弹错误态 |
| `session.list` 固定 `limit = 200`，无分页 | 会话多了以后只能靠后端截断；要加分页得改 Repository 与 `Loadable` 语义 |
| 能力/设置入口不是 toggle | 能力项永远显示"能力"（ADR-044），回会话靠点 profile 头像；画成开关会误导 |
| 快捷键的 `codePoint` 是**字符**不是物理键位 | `Shift+[` 得到 `{`，所以 `appShortcutOf` 同时接受移位前后两种字符 |
| 心跳固定 5s | 本地后端 ready 前的探活失败是**正常**的，不要据此报错 |
| 重命名**必须**走 REST `PATCH /api/sessions/{id}` | RPC `session.title` 是 session-scoped：会话不在内存就回 `4001 session not found`（实测）。后者只适合"刚建、还没落库"的会话（那时它是 live 的） |
| REST 写会话要过 **mutation fence** | 缺 `request_id` / `expected_revision` 会回 `409 client_upgrade_required`（后端把无 fence 的客户端当成旧版）；先读 `GET /api/sessions/{id}/mutation-snapshot` 的 `runtime_revision` 再提交 |
| `GET /api/sessions` 是 **OpenAI 信封** | 行在 `data` 里，不是 `sessions`；按 `sessions` 解析永远拿到空集（置顶"重启后消失"就是这么来的） |
| 后端 `pinned` **写不进**（当前版本） | 带 fence 的 `PATCH {pinned}` 回 200 但不落库，`DELETE` 带 fence 回 `400 invalid_params`。所以置顶先用本地偏好，删除走 **RPC**（需先点开会话让它 live） |
| 删除会话要先点开 | `session.delete` 是 session-scoped，冷会话需先 `session.resume`（点开即 resume）；UI 上表现为"点开再删"能成功 |
| 点输入框前先确认坐标 | composer 左侧是模型 pill，点偏了会弹模型菜单（GUI 自动化踩过），见技能 §2.5 |
| 归档行**不会**从后端列表再出现 | `session.list` / `GET /api/sessions` 都 `include_archived=False`，所以"已归档"只能列本地快照；恢复入口必须自己维护，否则用户点完归档就再也找不回来 |
| 终端展开时任何 Compose 对话框都会被遮 | `SwingPanel` 是 heavyweight。`AppShell` 统一处理：重命名/删除/归档/模型确认任一对话框打开时先 `collapse()` 终端，关掉后 `expand()` 回去 |
