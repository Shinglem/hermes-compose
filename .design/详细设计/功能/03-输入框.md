# 03 · 输入框

> 覆盖 `composer` 域：输入框结构、`@` / `/` 补全状态机、粘贴与拖放（文本 / 图片 / 大段 / 路径）、
> 发送历史、草稿、发送链路（`prompt.submit`）。
>
> 依据：[`00-功能域总览.md`](00-功能域总览.md) §2.4、§3.4（草稿按会话隔离）；
> 决策：[ADR-019](../../草案/07-decisions.md)（chip 方案）、硬约束 3 / 4 / 7；
> 端到端验证手法见技能 [`dev-desktop-gui-e2e-testing`](../../../.ai/skill/dev-desktop-gui-e2e-testing/SKILL.md)。

---

## 1. 可见行为

| 能力 | 实现 | 说明 |
|---|---|---|
| 多行输入 + 自动高度 | ✅ | `heightIn(min = 40.dp, max = 224.dp)`（约 1–10 行，再多框内滚动） |
| 发送 / 换行 | ✅ | `Enter` 发送、`Shift+Enter` 换行；`composition != null`（IME 组字中）时 Enter 交回输入法 |
| `@` 引用补全 | ✅ | 防抖 150ms，`complete.path`（带 cwd / session_id / profile） |
| `/` 命令补全 | ✅ | 仅行首触发，`complete.slash`，用回执的 `replace_from` 作为替换起点 |
| 引用/命令的高亮 | ✅（**上色，不是 chip**） | `VisualTransformation` 上色：`@…` 用 primary、行首 `/…` 用 tertiary + Monospace；文字仍是原文 |
| 粘贴图片 | ✅ | `Clipboard.hasImage()` → 客户端落盘 → `image.attach_bytes`，底部出现附件行；路径与 mime 随本轮 `prompt.submit` 的 `attachments` 回传（v0.5.7 起；`.bmp` / `.heic` 在附加阶段即被拒绝） |
| 粘贴大段 | ✅ | ≥2000 字或 ≥30 行 → `paste.collapse` 换占位符 + 行内提示 |
| 粘贴单行路径 | ✅ | 图片走 `image.attach_bytes` 并随提交送达，其它走 `file.attach` 并插入引用文本 |
| 拖入文件 | ✅ | `dragAndDropTarget` + 悬停提示；图片/文件分流同上 |
| 发送历史 | ✅ | `↑` / `↓`，仅"无浮层 + 单行 + 光标在末尾"时接管；上限 50 条（仅本次运行内） |
| 生成中继续发 | ✅ | 发送按钮**不再因生成中禁用**：`ChatViewModel.send` 在忙碌时改走 `session.steer`（后端 `display.busy_input_mode` 负责纠偏/排队） |
| 草稿 | ✅ | 按会话存 `drafts.<sessionId>`，800ms 防抖；清空即删键 |
| 模型 / 推理 pill | ✅ | 底部 pill 打开模型目录（懒加载 `model.options`），切换走 `config.set`，不支持的推理强度隐藏 pill |
| Markdown 源码直发 | ✅ | 只 `trim()`，不转义、不改写、不做 WYSIWYG（硬约束 7） |

**与硬约束 4 括号描述的偏差（有意为之，勿"修正"）**：硬约束写的是
`BasicTextFieldState + AnnotatedString + InlineTextContent` 做 chip，实际实现是
**`BasicTextField(value = TextFieldValue)` + `VisualTransformation` 上色**，没有原子 chip。
原因是 `BasicTextField` 的 inline content 在编辑 / 删除 / 中间插入时不稳（ADR-019），
chip 会带来"删不掉半个引用"这类更难修的问题。**输入框内核仍然是 `BasicTextField`（硬约束 4 的主体）**，
且必须自己接管 IME 组合态（中文输入是硬需求）。

## 2. 状态字段

```kotlin
// ComposerModels.kt:105
data class ComposerUiState(
    val value: TextFieldValue,                 // 文本 + 选区 + IME composition
    val completion: CompletionState?,          // trigger / entries / selected / start / end
    val attachments: List<ComposerAttachment>, // 本轮图片附件
    val notice: String?,                       // 行内提示（折叠成功、附件失败…）
    val history: List<String>,                 // 本次运行内发送历史（末位最新）
) {
    val text: String; val canSend: Boolean     // text.isNotBlank()
}
```

ViewModel 私有状态：`historyCursor`、`draftSessionId`、`completionJob`、`draftJob`；
常量 `COMPLETION_DEBOUNCE_MS = 150`、`DRAFT_DEBOUNCE_MS = 800`、`HISTORY_LIMIT = 50`。

## 3. 组件树

```
Composer
├── 附件行（attachments：Surface + 前缀文案，非富 chip）
├── BasicTextField（ComposerHighlight 作为 visualTransformation）
│   └── decorationBox → placeholder
├── CompletionPopover（有 completion 时浮在上方）
└── 工具栏：附件按钮 / modelBar（模型 + 推理 pill）/ 发送或停止按钮
```

`ComposerController` 是 Compose 与 ViewModel 之间的**回调包**（`onValueChange` / `onAcceptCompletion` /
`onMoveCompletion` / `onDismissCompletion` / `onStepHistory` / `onPasteSpecial` / `onPickFiles` / `onDropFiles`），
不在 Composable 里直接持有 ViewModel。

## 4. 方法签名（要点）

```kotlin
@Composable fun Composer(
    controller: ComposerController, canSubmit: Boolean, busy: Boolean, stopping: Boolean,
    onSend: (String) -> Unit, onStop: () -> Unit,
    modifier: Modifier = Modifier, modelBar: (@Composable () -> Unit)? = null,
)

class ComposerViewModel(...) : ViewModel() {
    fun openSession(profile: String?, sessionId: String?)
    fun onValueChange(value: TextFieldValue)
    fun acceptCompletion(index: Int? = null): Boolean
    fun stepHistory(direction: Int): Boolean
    fun markSent(text: String)                  // 必须同时取消 draftJob
    fun handlePasteSpecial(text: String, range: TextRange)
    fun attachPaths(paths: List<String>)
}

fun activeToken(text: String, cursor: Int): ActiveToken?      // 纯函数（补全触发判定）
fun isLargePaste(text: String): Boolean                       // 纯函数
```

RPC：`complete.path`、`complete.slash`、`paste.collapse`、`file.attach`、`image.attach`、
`clipboard.paste`、`input.detect_drop`、`prompt.submit`、`session.interrupt`、`model.options`、`config.set`。
偏好：`drafts.<sessionId>`。发送超时：`Timeouts.PROMPT_SUBMIT_MS = 1800s`。

## 5. 空 / 载入 / 错 / 禁用

| 情形 | 表现 |
|---|---|
| 空文本 | `decorationBox` 里的占位提示 |
| 补全无结果 / 请求失败 | 浮层直接不显示（静默，仅 debug 日志） |
| 没有活会话 | 附件/图片/路径粘贴 → 行内提示「还没有活会话，先发一条消息再…」 |
| 附件失败 | 行内提示「图片附加失败：…」；文件选择器异常同样提示 |
| 发送中 | 发送按钮换 Stop；`ChatViewModel.send` 自身防重（`sending || isBusy` 直接 return） |
| 未选会话 | `key == null` 不发送；`canSubmit = !state.sending` |
| 模型目录 | 载入中显示载入项；空目录 / 失败各有文案与重试 |

## 6. 验收条目

- **C1 中文输入**（硬约束，必须人工/端到端验）：候选框弹出、选词后文本正确、`Enter` 在组字中不误发。
- **C2 IME 守卫**：组字期间不弹补全浮层；组字期间 Enter 交给输入法而不是发送。
- **C3 补全区间**：`/skin` 提示 → 异步返回前继续输入 → 接受后得到 `/skin xxx` 而不是 `/skinill`。
- **C4 浮层与 Enter 的耦合**：浮层无有效项时 Enter 必须**继续走发送**（不能吞键）。
- **C5 粘贴分派**：图片 → 附件；≥2000 字 → 折叠占位符；单行路径 → 附件 + 引用文本；普通文本 → 默认粘贴。
- **C6 草稿**：输入后切走再回来文本还在；发送后草稿被清空且不会被防抖写回。
- **C7 历史**：`↑` 取上一条，`↓` 到底回到空串；多行编辑时不接管方向键。

## 7. 坑

| 坑 | 说明 |
|---|---|
| `Ctrl+V` 必须自己预判 | 后端 `clipboard.paste` 在剪贴板**没有图片**时可能直接断 WS，所以先 `Clipboard.hasImage()` 再决定；否则整条连接会被掐 |
| gateway 跑在 Session 0 时剪贴板隔离 | `clipboard.paste` 会失败，必须回退"本地落盘 + `image.attach`" |
| `markSent` 必须取消 `draftJob` | 否则 800ms 后防抖把刚发出去的文本又写回草稿，用户以为没发出去 |
| 接受补全要在**应用时刻**重算区间 | 用请求发出时的光标/end 会拼出残尾（实测 `/skinill`） |
| 接受后不要立刻重新触发补全 | 同一条目会立刻匹配自己，Enter 永远停在"接受" |
| "接管按键"必须与"确实处理了"绑定 | 浮层存在但无有效项时仍 `return true` 会吞掉 Enter（表现为"按 Enter 什么都不发生"） |
| `composition != null` 时不弹补全 | IME 组字期间弹浮层会抢焦点、丢按键 |
| `↑`/`↓` 只在单行 + 末尾接管 | 否则多行编辑里无法移动光标 |
| macOS 只判了 `isCtrlPressed` | `Cmd+V` 未处理（潜在平台缺口，Windows 优先故暂不影响） |
| chip 做成 inline content 会坏 | `BasicTextField` 对 inline content 的编辑/删除不稳（ADR-019），保持"上色"方案 |
| 注入测试时 `Shift+[` 得到 `{` | `appShortcutOf` 同时接受移位前后字符；GUI 注入见技能 §2.6 |
| 窗口不能关到托盘时**销毁** | `windowVisible` 曾用 `if (...) { Window(...) }` 整块移除：每次从托盘唤起都是新 AWT 窗口，它的 `InputMethodRequests` 是空的，用户敲的**第一个键**会绕过输入法直接落进文本框（第二个键才正常）。现在窗口常驻组合，只用 `Window(visible = windowVisible)` 切可见性（见 `Main.kt`）|
