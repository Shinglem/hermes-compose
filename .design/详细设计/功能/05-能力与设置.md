# 05 · 能力与设置

> 覆盖 `capabilities`（技能与工具 / 消息平台 / 定时任务）与 `settings`（模型 / 外链编辑器 / 代理）。
> 数据全部走 REST `/api/...`（这些端点在 RPC 表里没有），契约见
> [`../../草案/08-data-contract.md`](../../草案/08-data-contract.md) §3。
>
> 本篇先落 P4 的三页；`settings` 随 P6 一起补。

---

## 1. 可见行为

| 页 | 用户能做什么 |
|---|---|
| 技能与工具 | 搜索；分段切换「技能 / 工具集 / 发现」；每行开关即时生效；展开看 SKILL.md 原文；「发现」里按分类筛选官方技能库、展开看说明、一键安装 |
| 消息平台 | 看每个平台的状态与错误；展开配置表单（按后端给的 `env_vars` 动态生成）；保存；测试连接；开关 |
| 定时任务 | 看列表（cron 描述、profile 归属、暂停标记、最近一次结果）；新建 / 编辑；用蓝图创建；暂停 / 恢复；立即运行；删除；展开看运行记录 |

已选分类与各页的展开状态在切到会话模式再切回来时**保留**（`CapabilityState` 活在 ViewModel 里）。

## 2. 状态字段

```kotlin
data class CapabilityState(
    val section: CapabilitySection,        // SKILLS / PLATFORMS / CRON
    val skillsTab: SkillsTab,              // SKILLS / TOOLSETS / DISCOVER
    val skillQuery: String,
    val skills: Loadable<List<SkillDto>>,  // 三页各自独立装载
    val toolsets: Loadable<List<ToolsetDto>>,
    val platforms: Loadable<List<MessagingPlatformDto>>,
    val cronJobs: Loadable<List<CronJobDto>>,
    val blueprints: List<BlueprintDto>,        // 新建表单的下拉源
    val deliveryTargets: List<DeliveryTargetDto>,
    val busyKey: String?,                  // 正在写的那一项（行内转圈 + 禁用）
    val expandedSkill: String?, val skillContent: Loadable<String>,
    val catalog: Loadable<List<SkillCatalogEntryDto>>,   // /api/skills/hub/official
    val catalogCategory: String?,          // null = 全部分类
    val expandedCatalogItem: String?,      // 目录里展开的 identifier
    val expandedPlatform: String?, val platformDrafts: Map<String, Map<String, String>>,
    val cronDraft: CronDraft?, val expandedJob: String?, val cronRuns: Loadable<List<CronRunDto>>,
    val notice: String?, val noticeIsError: Boolean,
)
```

**为什么 `busyKey` 是一个字符串而不是每页一个布尔**：写操作的粒度是"某一项"，
用 key 能直接驱动"这一行转圈、这一行禁用"，且天然防止同一行被连点。

## 3. 写操作策略

```
用户操作 → 乐观更新（可选） → 写请求 → 成功：回读列表 → Ready
                                    ↘ 失败：回滚到操作前的快照 + notice（错误色）
```

- **开关类**（技能 / 工具集）：先乐观切过去，失败回滚整页快照。这两页的回读成本低，
  而且后端的 `enabled` 会牵连派生字段（工具集的 `available` / `configured`），所以成功也回读。
- **表单类**（平台配置 / 新建任务）：**不乐观更新**，只置 `busyKey`，成功后回读。
  平台保存失败时还会额外回读一次 —— 后端可能已写入 `.env` 但 `enabled` 落盘失败，
  只回滚 UI 会让界面与磁盘不一致。
- **一次性操作**（触发 / 暂停 / 恢复 / 删除）：直接写 + 回读；删除需二次确认。

```
CapabilitiesWorkspace
├── 中栏：分类列表（CapabilityRow × 3，自绘 Surface + Column，不用 NavigationRail）
└── 右栏：Column
    ├── NoticeBar（可选，成功/失败一次性提示）
```

## 5. 方法签名（`CapabilityViewModel`）

| 方法 | 说明 |
|---|---|
| `setProfile(profile)` | profile 变了就作废三页数据（跨域约定 §3.1） |
| `selectSection(section)` | 进页即拉该页需要的端点（不做三页齐拉） |
| `toggleSkill(name, enabled)` / `toggleToolset(name, enabled)` | 乐观更新 + 失败回滚 + 成功回读 |
| `toggleSkillDetail(name)` | 展开才拉 `skills/content`，收起清空 |
| `setPlatformField(id, key, value)` | 只记 draft；空值即移除该键 |
| `savePlatform(id, enabled?)` | 提交 draft 里非空的键；成功后清 draft |
| `testPlatform(id)` | `POST .../test`，用回执 `detail` 或 `ok` 生成提示 |
| `startCreateCron` / `updateCronDraft` / `saveCronDraft` | 新建任务（cron 5 段前端先校验） |
| `setCronPaused(id, paused)` / `triggerCron(id)` / `deleteCron(id)` | 生命周期操作 |
| `toggleCronRuns(id)` | 展开才拉 `runs?limit=10` |
| `selectSkillsTab(tab)` | 切到「工具集」/「发现」且该页没有缓存时才拉数据（目录 150+ 项，不跟技能页一起打） |
| `setCatalogCategory(category)` / `toggleCatalogItem(identifier)` | 分类筛选（点已选中的分类 = 取消）、展开目录项说明 |
| `refreshCatalog()` / `installCatalogSkill(identifier)` | 拉 `/api/skills/hub/official`；安装后 delay 1.5s 回读目录与已安装列表 |

## 6. 空 / 错 / 载入

| 状态 | 表现 |
|---|---|
| 首次载入 | 行内 `CircularProgressIndicator`（不做整页骨架屏） |
| 失败且无缓存 | `EmptyState` + 错误文案 + 重试按钮 |
| 失败但有缓存 | 保留旧数据 + 顶部 `RetryBanner`（切 profile 回来不会白屏） |
| 列表为空 | 各页自己的空态文案；定时任务页额外提示"新建任务"入口在右上角 |
| 搜索无结果 | "没有匹配的技能"+ 提示换关键词（与"后端一个都没有"区分开） |

**搜索不过滤状态机**：过滤在拿到数据之后做，所以"装载中"不会被误判成"没有匹配结果"。

## 7. 验收条目

- A1 技能开关：切一下 → 后端 `config` 里禁用列表变化 → 重进页面仍为新状态；
- A2 工具集开关：同上，且 `enabled` 与 `available` 的组合没被 UI 覆盖；
- A3 平台配置：填一个必填密钥保存 → `.env` 出现该键；空值不覆盖已有值；
- A4 平台测试：`POST .../test` 的回执变成可读提示（成功/失败都要能看懂）；
- A5 定时任务：新建一个每分钟任务 → `cron/jobs` 里能查到 → 触发一次 → `runs` 出现记录；
- A6 错误路径：故意填错密钥 / 断网，界面给中文可读提示且能重试；
- A7 能力 ↔ 会话切换：切走再回来，分类、搜索词、展开状态都还在。
- A8 技能库（发现）：切到「发现」才拉目录；分类 chip 可筛选也可取消；点「安装」后行内转圈，
  1.5s 后 `installed` 变「已安装」且「技能」列表里出现该项（以列表为准，回执只代表已提交）。

## 8. 坑

| 坑 | 说明 |
|---|---|
| `skills/toggle` 是 **PUT** 不是 POST | 按 REST 直觉写 POST 会 405；契约以本文 §3 与后端路由为准 |
| 平台 `env` 是**增量**语义 | 空串会被后端当"清空"，所以只提交用户填过的键，未填的不发 |
| 已保存的密钥**不回显** | 后端只给 `is_set` / `redacted_value`；输入框用占位提示，别填星号假冒真值 |
| `cron/jobs` 返回**裸数组**，`messaging/platforms` 是**对象** | 同一批 REST 端点形状不统一，DTO 必须分别适配 |
| 平台 `PUT` 返回 `{ok, platform, hot_served}`，**不是**平台快照 | 想拿最新状态必须回读列表；`hot_served=false` 表示要重启网关才生效，得提示用户 |
| 平台 `POST .../test` 的回执是 `{ok, state, message}` | 失败原因在 `message`（英文），优先展示它比自造"测试未通过"有用 |
| 技能开关 `PUT` 回执是 `{ok, name, enabled}` | 与平台的不一样；统一用宽松 `AckDto` 接，别假设同一形状 |
| `enabled` 才是任务开关 | `state` 是派生值（`paused` / `completed` / `error`），只看 `state` 会误判 |
| 跨 profile 聚合会重复 id | `GET /api/cron/jobs` 默认 `profile=all`，后端已按 id 去重并偏好 default；前端不要再合并 |
| 配置写入牵连 `.env` 落盘 | 写超时用 45s（`Timeouts.WRITE_MS`），比读慢；失败后要回读而不是只回滚 |
| 技能库是**本地扫描**，不是在线商店 | `/api/skills/hub/official` 扫 payload 里的 optional skills，离线也能看；不要加"联网/下载"的状态文案 |
| `hub/install` 是**异步起 CLI** | 回执 `{ok}` 只表示已提交；必须 delay 后再回读目录与技能列表，否则界面上"装完了但没变化" |
| `installed` 由**后端按 profile 判定** | 前端不要自己比对技能名去推断是否已安装（同名技能在不同 profile 下状态不同） |
| 目录项 150+ 条 | 分类筛选必须先做（`catalogCategories()` 按数量降序生成 chip 行，横向滚动），别一次平铺全量 |

## 9. 已知偏差（记录而非假装合规）

- `CapabilityViewModel` 里的提示文案（"已保存" / "开关失败：…"）是**中文字面量**，
  没有走 Compose Resources。原因是这些提示带运行时参数（后端 `message`、异常文案），
  而资源只适合固定句式。后续若要统一，应把 `notice` 改成 `Notice(kind, arg)` 结构体、
  由 UI 层渲染资源 —— 这是纯粹的机械重构，等文案需要改的时候一起做。

---

## 9.1 运行记录的契约（实测，与直觉不同）

`GET /api/cron/jobs/{id}/runs` **返回的是 session 行，不是 executions 表**：

| 字段 | 说明 |
|---|---|
| `id` | `cron_<job>_<YYYYMMDD_HHMMSS>` |
| `started_at` / `ended_at` | **Unix epoch 秒（浮点）**，不是 ISO 字符串 |
| `model` / `cost_status` / `billing_provider` | 这一轮用的模型与计费状态 |
| `handoff_error` / `compression_failure_error` | 失败原因（无独立 `status` 字段） |

所以状态只能**推导**：有错误字段 → 失败；有 `ended_at` → 已完成；否则 → 运行中。
而列表行的 `latest_execution`（executions 表）确实有 `status`，两者形状不同，DTO 要分开。
