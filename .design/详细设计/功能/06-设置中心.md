# 06 · 设置中心（后端设置面）

> 本文覆盖 v0.2.0 的**后端设置面**：配置档案、模型（主 / 辅助 / 备用 / MoA）、安全（审批 / 隐私 / 检查点）、
> 提供方（密钥 / 凭据池 / 自定义端点），以及 v0.5.1 起的**维护面**（记忆 / 诊断与维护 / 用量与成本 / 会话维护）。
> 桌面端本地设置（`config_custom.json` / `options_custom.json`）见
> [工程与代码/05](../工程与代码/05-打包与配置.md) §3.4.1；左栏结构与 rail 语义见
> [ADR-046 ~ ADR-048](../../草案/07-decisions.md)。
>
> **这些页改的全是后端**（`config.yaml` / `.env`），不是桌面端偏好 —— 见 [ADR-043](../../草案/07-decisions.md)。

## 1. 可见行为

左栏一律「一级分组 → 二级页面」两级结构，不允许把设置项直接挂在根上（ADR-046）：

| 一级分组 | 二级页 | 数据源 |
|---|---|---|
| 选项 | `SettingsCatalog.groups` 里的各组（后端连接 / 应用 / 启动 …） | 本地 `*.custom.json` |
| 终端 | 外观 | 本地 `state.json`（ADR-042） |
| 提供方 | 密钥 | `GET/PUT /api/env` |
| 提供方 | 凭据池 | `/api/credentials/pool`（多把 key 轮换） |
| 提供方 | 自定义端点 | `/api/providers/custom-endpoints` 系列 |
| 配置档案 | 档案 | `/api/profiles` 系列 |
| 模型 | 主模型 / 辅助模型 / 备用模型 / 混合代理 MoA | `/api/model/*` + `PUT /api/config` |
| 安全 | 审批 / 隐私与网络 / 检查点 | `GET/PUT /api/config` |
| 智能体 | 记忆 | `/api/memory` 系列 |
| 应用 | 用量与成本 | `/api/analytics/usage` |
| 应用 | 会话维护 | `/api/sessions/stats`、`/api/sessions/empty*` |
| 应用 | 诊断与维护 | `/api/ops/*`、`/api/actions/{name}/status`、`/api/curator` 系列 |
| 调试（条件出现） | 官方桌面端 | 本地探测（ADR-045） |

> 「调试」组只在 payload 里存在 `official-desktop/Hermes.exe`（或 `app.debug.official_desktop` 指到真文件）时出现，
> 否则整组不渲染。对照实例的数据根固定为 `<home>/data/official-desktop/`：`userdata/` 与 `hermes-home/`
> 必须与用户本机官方客户端分开（单实例锁按 userData 判重、`HERMES_HOME` 共用会拉起生产后端），
> 子进程输出 append 到同目录 `official-desktop.log`（不重定向会因管道写满把官方客户端卡住）。

共同约定：

- 页头一行标题 + 一行说明，说明里写清「对谁生效、什么时候生效」。
- 写入后**回读**，不乐观更新：这些接口的响应形状与写入值并不总是等号关系。
- 每页只有一个「保存」，改完不保存就切页 = 丢弃（没有自动保存，除了 MoA 这种整表提交的页也仍是显式保存）。

## 2. 状态字段

每个后端设置域一个 ViewModel + 一个 `State` data class，字段命名统一：

| 字段 | 含义 |
|---|---|
| `load` / `xxx: Loadable<T>` | 读数据；`Loadable` 有 `Idle/Loading/Ready/Failed` |
| `edits: Map<String, String>` | 表单草稿（键 = 配置点分路径） |
| `busyKey: String?` | 正在写哪一项；非空时按钮禁用 |
| `error` / `notice` | 一次性提示，切页或下次操作清空 |
| `profile` | 视图模型内部记住的 profile；变了就整页重置并重读 |

各页特有：

- 模型页：`provider` / `model` / `contextDraft`（主模型草稿）、`pending`（贵模型二次确认）、
  `fallback: Loadable<List<FallbackEntry>>` + `fallbackKeepArray`、`aux: Loadable<AuxModelsDto>`。
- MoA 页：`presets: Map<String, MoaPresetDto>`（**整份预设表**）、`defaultPreset`、`activePreset`、
  `selected`、`dirty`；派生 `presetProblem`。
- 自定义端点页：`endpoints: Loadable<List<CustomEndpointDto>>`、`draft: EndpointDraft?`
  （非空 = 表单态）、`probe` / `probeOk`、`pendingDelete`。
- 提供方密钥：`env: Loadable<Map<String, EnvVarDto>>`、`query`（搜索）、`drafts`。

```
SettingsSection（左栏，可折叠）
└── SettingsDetailPane（右栏，一个大 when(state.selected)）
    ├── CatalogPage        ← SettingsCatalog.groups[index]
    ├── ProviderKeysPage
    ├── CustomEndpointPage ├── EndpointList   （draft == null）
    │                      └── EndpointForm   （draft != null）
    ├── ProfilesPage
    ├── MainModelPage / AuxModelPage / FallbackModelPage / MoaModelsPage
    ├── SecurityFormPage（审批 / 隐私 / 检查点共用，字段来自 ConfigFieldSpec 列表）
    └── DebugPage
```

`SettingsDetailPane` 的参数已经很多，所以**模型页**与**自定义端点页 / MoA 页**的回调各自打包成
`ModelPageCallbacks` / `EndpointPageCallbacks` / `MoaPageCallbacks`，不再平铺十几个函数。

### 4.1 维护页组（v0.5.1）

五块能力共用 `MaintenanceRepository` + `MaintenanceViewModel`：它们都是「动作型」页面，
没有表单草稿，只有一次点击 → 一次请求 → 一行结果。

````kotlin
class MaintenanceRepository {
    suspend fun memoryStatus(profile: String?): MemoryStatusDto
    suspend fun setMemoryProvider(provider: String, profile: String?): String
    suspend fun resetMemory(target: String, profile: String?): MemoryResetResultDto   // destructive

    suspend fun runDoctor(profile: String?): BackupStartedDto          // {ok,pid,name}
    suspend fun runSecurityAudit(profile: String?): BackupStartedDto
    suspend fun runBackup(profile: String?): BackupStartedDto          // 多回一个 archive
    suspend fun pruneCheckpoints(profile: String?): BackupStartedDto
    suspend fun runCurator(profile: String?): BackupStartedDto
    suspend fun actionStatus(name: String, lines: Int = 200): ActionStatusDto
    suspend fun awaitAction(name: String, timeoutMs: Long = 180_000): ActionStatusDto

    suspend fun checkpoints(profile: String?): OpsCheckpointsDto
    suspend fun curator(profile: String?): CuratorStatusDto
    suspend fun setCuratorPaused(paused: Boolean, profile: String?): Boolean

    suspend fun credentialPool(profile: String?): CredentialPoolDto
    suspend fun addCredential(provider: String, apiKey: String, label: String?, profile: String?): CredentialPoolAddResultDto
    suspend fun deleteCredential(provider: String, index: Int, profile: String?)

    suspend fun usage(days: Int, profile: String?): UsageAnalyticsDto
    suspend fun sessionStats(profile: String?): SessionStatsDto
    suspend fun emptySessionCount(profile: String?): Long
    suspend fun deleteEmptySessions(profile: String?): Int
}
````

要点：

- **后台动作是异步的**：`POST /api/ops/{doctor,security-audit,backup}`、
  `POST /api/ops/checkpoints/prune`、`POST /api/curator/run` 都只回 `{ok,pid,name}`；
  日志要轮询 `GET /api/actions/{name}/status?lines=N` 直到 `running=false`。
  UI 只展示日志尾部 25 行，完整输出留在服务端 `logs/`。
- **记忆 provider 是档案级、也是插件级**：provider 列表来自 `plugins/memory/<name>/plugin.yaml`
  （bundled 目录 / 用户目录 / pip entry point 三来源），后端用 `status` 表达能否启用：
  `ready` / `needs_config`（缺 env）/ `unavailable`（缺依赖或被 `plugins.disabled` 停用）/ `missing`。
  内置 `MEMORY.md` / `USER.md` 也按 profile 隔离（实测 default 3248 B / butler 3475 B），
  页面顶部必须写明"当前配置档案"。
- **本期范围决定（2026-11-07）：记忆页只支持内置记忆**。外部 provider 只做只读状态展示，
  不提供启用 / 配置 / 依赖安装入口 —— 它们要装 `brv` CLI 或订阅 RetainDB 云服务，
  与「插件体系」一起规划（见 CHANGELOG 的「未发布」段）。
  因此 `PUT /api/memory/provider` 与 `PUT /api/env` 这两条写入路径在客户端**不接线**；
  将来做插件功能时按新的配置表单设计重做（后端的 `_require_memory_provider_ready`
  只接受 `status=ready`，届时仍要按它禁用按钮）。
- **`RETAINDB_API_KEY` 这类键在密钥页看不到**：它在 `/api/env` 里 `provider=""`、`category=tool`，
  会被 provider 分组过滤。本期不给入口，文案要写清"写在对应档案的 `.env` 里"，
  不要指引用户去密钥页找一个不存在的输入框。
- **页面内「应用到」档案（照官方桌面端）**：维护页组顶部有一行档案 chips，
  切换的是**本组页面的配置作用域**（`MaintenanceViewModel.setScopeProfile`），
  **不修改** shell 的 `activeProfile` —— 会话页当前使用的档案不受影响。
  全局档案变化（点 rail）时本组作用域跟随，离开设置页再回来也回到全局档案。
  chips 的档案清单来自 shell 的 `profilesOrEmpty`（只读），由 AppShell 映射成 `ProfileChoice`，
  避免 settings 依赖 shell 的类型。
- **内置层四项配置**：`memory.memory_enabled`（持久记忆开关）、`memory.user_profile_enabled`（用户画像开关）、
  `memory.memory_char_limit`（记忆预算，默认 2200）、`memory.user_char_limit`（画像预算，默认 1375）。
  走 `ConfigRepository.patch` 的**稀疏 diff**，只发改动项；页面用 `MEMORY_FIELDS` 表驱动，
  与安全页共用 `buildConfigPatch`（数字解析失败就不发，布尔按 `"true"` 判定）。
  保存后**回读** —— 后端会给默认值，只有回读才看到真值。
- **破坏性动作必须二次确认**：记忆重置（删 `MEMORY.md` / `USER.md`）、检查点清理（删快照）、
  空会话删除、**从备份恢复**、按条件清理。文案要写清"删什么、能不能恢复"。
- **记忆文件读写走 `/api/fs/*`，且要绝对路径**：相对路径（`memories/MEMORY.md`）在该接口上 404；
  客户端用 `HERMES_HOME`（`AppContainer.hermesHome`）+ 档案推导：
  默认 `<home>/memories/`，命名档案 `<home>/profiles/<name>/memories/`。
  保存走 `POST /api/fs/write-text`（后端原子替换），保存后重读体积。
- **按条件清理先 dry-run**：`POST /api/sessions/prune {older_than_days, dry_run:true}` 只回统计，
  确认框用它给用户看"会删多少"，再以 `dry_run:false` 执行。
- **会话导入的格式陷阱**：后端 `POST /api/sessions/import` 要 `{sessions: [...]}`（会话行），
  而本客户端「导出」产出的是消息列表 —— 不能直接回灌，页面文案必须写清。
- **档案作用域条**：`SettingsPage.isProfileScoped()` 决定要不要显示「应用到」，
  `hasOwnProfileScope()` 标记自带条目的维护页（避免重复）。
- **凭据池不回显明文**：后端只给 `token_preview`；新增是写动作，删除按 1 起算的 `index`。
- **用量时间窗**：`days` 后端钳到 1–365，UI 只给 7 / 30 / 90。
- **profile 作用域**：五块都带 `?profile=`，切 profile 时整体作废（与密钥页一致）。

## 5. 空 / 错 / 载入

| 情形 | 表现 |
|---|---|
| 还没连上后端 | 不请求（`LaunchedEffect(mode, isConnected)` 门控），显示载入态而不是"加载失败" |
| 读失败 | `EmptyState` + 错误正文（`AppError.toNotice()`）+「重试」 |
| 列表为空 | 一行灰字说明「还没有…」，不画空卡片 |
| 表单不合法 | 保存按钮禁用 + 就地一行错误（MoA / 自定义端点）；安全页则"非法值不发"（只发能解析的字段） |
| 后端 4xx/5xx | 顶部一行错误（保留已填内容，不清空草稿） |

## 6. 验收条目

- S1 设置左栏任意入口都能点开对应页；不存在裸在根上的行。
- S2 每页的写入都能在**重新读取**后看到（回读一致）。
- S3 备用模型：磁盘是单个 dict 的 profile 保存后仍是 dict；是 list 的仍是 list。
- S4 MoA：删到只剩一个预设时「删除」禁用；任一半填预设都会挡住保存。
- S5 自定义端点：编辑已有端点且不重填 key 时，保存后 `has_api_key` 仍为 true。
- S6 提供方密钥：已保存的键只显示「已配置」，输入框为空（不回显明文）。
- S7 切换 profile 后，各页数据全部换成新 profile 的（不残留上一个档案的值）。
- S8 记忆页：`available=false` 的 provider「启用」按钮禁用，并说明缺什么；重置要先弹确认，
  确认文案里写明删哪个文件。
- S9 诊断页：点「运行诊断」后先显示"正在运行"，结束后显示退出码与日志尾部；切走再回来结果还在
  （状态在 ViewModel 里，不随页面销毁）。
- S10 凭据池：新增后列表里出现一条带打码预览的记录；明文输入框清空；删除有二次确认。
- S11 用量页：切 7 / 30 / 90 天会重新请求；金额与 token 数不为空；没有数据时显示一行灰字。
- S12 会话维护：空会话数为 0 时删除按钮禁用；删除后计数与统计同步刷新。

## 7. 坑

| 坑 | 说明 |
|---|---|
| `PUT /api/config` 是 deep-merge | 只能发**改动过**的键；整份回写会把别的页刚改的值覆盖回旧值 |
| 上下文覆盖写**顶层** `model_context_length` | 写成 `{model:{context_length}}` 能落盘但绕过"0 删键 / 换模型重探"逻辑 |
| `fallback_providers` 两种形状 | 后端 `_fallback_entries` 同时认 dict 与 list；写回要保持原形状 |
| MoA 读宽容写严格 | 读时半填预设被静默替换成默认值，写时 422 拒绝 —— 客户端必须先自检（上游 #64156） |
| MoA 提交是整表权威 | `presets` 里没列出的预设会被**删除** |
| `api_key` 空串 ≠ 不改 | 后端把空串当"清空密钥"，`null` 才是不改 |
| 探测会改 base_url | `/validate` 回 `resolved_base_url`，后端保存时也用这个值（运行时直接拼 `/chat/completions`） |
| `model.options` 走 RPC 且有 1h 磁盘缓存 | 模型目录刚改过（如新增自定义端点）可能看不到，需要显式刷新 |
| 贵模型二次确认 | `confirm_required` 必须弹窗，确认后用 `confirm_expensive_model=true` 重发 |
| `terminal.read` 是 server→client 请求 | 由窗口应答，不是我们主动调用（见 [04-终端.md](04-终端.md)） |
| 块注释里写路径通配 | KDoc 写 `` `/api/profiles/*` `` 会开启**嵌套块注释**吞掉整个文件，编译器只报别的文件的 `Unresolved reference` |
| 后台动作不是同步返回 | `POST /api/ops/doctor` 等只回 `{ok,pid,name}`；把它的回执当"结果"会永远显示成功。必须轮询 `/api/actions/{name}/status` |
| `/api/memory/reset` 真的删文件 | `target=all/memory/user` 直接 `unlink`，没有回收站；provider 侧记忆不受影响，别承诺"清空全部记忆" |
| `DELETE /api/sessions/empty` 的口径 | 只删「无消息 + 已结束 + 未归档」；活跃会话跳过，子会话被孤立而非级联 |
| curator 的 `last_run_at` 是时间串 | 后端直接回 ISO 字符串（或 null），不要当 epoch 数字解析 |
| 记忆 provider 不是配置项，是插件 | `plugins/memory/<name>/` 里的 `plugin.yaml` 决定依赖（如 `brv`）与 `requires_env`；插件不存在时配置里写了也只会是 `missing`。**本期客户端不接线启用**，只展示状态 |
| 密钥页看不到 `RETAINDB_API_KEY` | 该键 `provider=""` / `category=tool`，被 provider 分组过滤；本期记忆页也不给入口，只能写 `.env` |
