# 06 · 设置中心（后端设置面）

> 本文覆盖 v0.2.0 的**后端设置面**：配置档案、模型（主 / 辅助 / 备用 / MoA）、安全（审批 / 隐私 / 检查点）、
> 提供方（密钥 / 自定义端点）。桌面端本地设置（`config_custom.json` / `options_custom.json`）见
> [工程与代码/05](../工程与代码/05-打包与配置.md) §3.4.1；左栏结构与 rail 语义见
> [ADR-046 ~ ADR-048](../../草案/07-decisions.md)。
>
> **这些页改的全是后端**（`config.yaml` / `.env`），不是桌面端偏好 —— 见 [ADR-043](../../草案/07-decisions.md)。

## 1. 可见行为

左栏一律「一级分组 → 二级页面」两级结构，不允许把设置项直接挂在根上（ADR-046）：

| 一级分组 | 二级页 | 数据源 |
|---|---|---|
| 选项 | `SettingsCatalog.groups` 里的各组（后端连接 / 应用 / 启动 …） | 本地 `*.custom.json` |
| 终端 | 外观 | 本地 `state.json`（ADR-042） |
| 提供方 | 密钥 | `GET/PUT /api/env` |
| 提供方 | 自定义端点 | `/api/providers/custom-endpoints` 系列 |
| 配置档案 | 档案 | `/api/profiles` 系列 |
| 模型 | 主模型 / 辅助模型 / 备用模型 / 混合代理 MoA | `/api/model/*` + `PUT /api/config` |
| 安全 | 审批 / 隐私与网络 / 检查点 | `GET/PUT /api/config` |
| 调试（条件出现） | 官方桌面端 | 本地探测（ADR-045） |

> 「调试」组只在 payload 里存在 `official-desktop/Hermes.exe`（或 `app.debug.official_desktop` 指到真文件）时出现，
> 否则整组不渲染。对照实例的数据根固定为 `<home>/data/official-desktop/`：`userdata/` 与 `hermes-home/`
> 必须与用户本机官方客户端分开（单实例锁按 userData 判重、`HERMES_HOME` 共用会拉起生产后端），
> 子进程输出 append 到同目录 `official-desktop.log`（不重定向会因管道写满把官方客户端卡住）。

共同约定：

- 页头一行标题 + 一行说明，说明里写清「对谁生效、什么时候生效」。
- 写入后**回读**，不乐观更新：这些接口的响应形状与写入值并不总是等号关系。
- 每页只有一个「保存」，改完不保存就切页 = 丢弃（没有自动保存，除了 MoA 这种整表提交的页也仍是显式保存）。

## 2. 状态字段

每个后端设置域一个 ViewModel + 一个 `State` data class，字段命名统一：

| 字段 | 含义 |
|---|---|
| `load` / `xxx: Loadable<T>` | 读数据；`Loadable` 有 `Idle/Loading/Ready/Failed` |
| `edits: Map<String, String>` | 表单草稿（键 = 配置点分路径） |
| `busyKey: String?` | 正在写哪一项；非空时按钮禁用 |
| `error` / `notice` | 一次性提示，切页或下次操作清空 |
| `profile` | 视图模型内部记住的 profile；变了就整页重置并重读 |

各页特有：

- 模型页：`provider` / `model` / `contextDraft`（主模型草稿）、`pending`（贵模型二次确认）、
  `fallback: Loadable<List<FallbackEntry>>` + `fallbackKeepArray`、`aux: Loadable<AuxModelsDto>`。
- MoA 页：`presets: Map<String, MoaPresetDto>`（**整份预设表**）、`defaultPreset`、`activePreset`、
  `selected`、`dirty`；派生 `presetProblem`。
- 自定义端点页：`endpoints: Loadable<List<CustomEndpointDto>>`、`draft: EndpointDraft?`
  （非空 = 表单态）、`probe` / `probeOk`、`pendingDelete`。
- 提供方密钥：`env: Loadable<Map<String, EnvVarDto>>`、`query`（搜索）、`drafts`。

## 3. 组件树

```
SettingsSection（左栏，可折叠）
└── SettingsDetailPane（右栏，一个大 when(state.selected)）
    ├── CatalogPage        ← SettingsCatalog.groups[index]
    ├── ProviderKeysPage
    ├── CustomEndpointPage ├── EndpointList   （draft == null）
    │                      └── EndpointForm   （draft != null）
    ├── ProfilesPage
    ├── MainModelPage / AuxModelPage / FallbackModelPage / MoaModelsPage
    ├── SecurityFormPage（审批 / 隐私 / 检查点共用，字段来自 ConfigFieldSpec 列表）
    └── DebugPage
```

`SettingsDetailPane` 的参数已经很多，所以**模型页**与**自定义端点页 / MoA 页**的回调各自打包成
`ModelPageCallbacks` / `EndpointPageCallbacks` / `MoaPageCallbacks`，不再平铺十几个函数。

## 4. 方法签名（要点）

```kotlin

class ConfigRepository {
    suspend fun read(profile: String?): JsonObject
    suspend fun patch(profile: String?, diff: JsonObject)   // 只发稀疏 diff，后端 deep-merge
}

// 模型
class ModelAdminRepository {
    suspend fun info(profile: String?): ModelInfoAdminDto
    suspend fun auxiliary(profile: String?): AuxModelsDto
    suspend fun moa(profile: String?): MoaConfigDto
    suspend fun saveMoa(profile: String?, update: MoaConfigUpdateDto): MoaConfigDto
    suspend fun assignModel(profile: String?, scope: String, provider: String, model: String,

// 自定义端点
class CustomEndpointRepository {
    suspend fun list(profile: String?): CustomEndpointsDto
```

## 5. 空 / 错 / 载入

| 情形 | 表现 |
|---|---|
| 还没连上后端 | 不请求（`LaunchedEffect(mode, isConnected)` 门控），显示载入态而不是"加载失败" |
| 读失败 | `EmptyState` + 错误正文（`AppError.toNotice()`）+「重试」 |
| 列表为空 | 一行灰字说明「还没有…」，不画空卡片 |
| 表单不合法 | 保存按钮禁用 + 就地一行错误（MoA / 自定义端点）；安全页则"非法值不发"（只发能解析的字段） |
| 后端 4xx/5xx | 顶部一行错误（保留已填内容，不清空草稿） |

## 6. 验收条目

- S1 设置左栏任意入口都能点开对应页；不存在裸在根上的行。
- S2 每页的写入都能在**重新读取**后看到（回读一致）。
- S3 备用模型：磁盘是单个 dict 的 profile 保存后仍是 dict；是 list 的仍是 list。
- S4 MoA：删到只剩一个预设时「删除」禁用；任一半填预设都会挡住保存。
- S5 自定义端点：编辑已有端点且不重填 key 时，保存后 `has_api_key` 仍为 true。
- S6 提供方密钥：已保存的键只显示「已配置」，输入框为空（不回显明文）。
- S7 切换 profile 后，各页数据全部换成新 profile 的（不残留上一个档案的值）。

## 7. 坑

| 坑 | 说明 |
|---|---|
| `PUT /api/config` 是 deep-merge | 只能发**改动过**的键；整份回写会把别的页刚改的值覆盖回旧值 |
| 上下文覆盖写**顶层** `model_context_length` | 写成 `{model:{context_length}}` 能落盘但绕过"0 删键 / 换模型重探"逻辑 |
| `fallback_providers` 两种形状 | 后端 `_fallback_entries` 同时认 dict 与 list；写回要保持原形状 |
| MoA 读宽容写严格 | 读时半填预设被静默替换成默认值，写时 422 拒绝 —— 客户端必须先自检（上游 #64156） |
| MoA 提交是整表权威 | `presets` 里没列出的预设会被**删除** |
| `api_key` 空串 ≠ 不改 | 后端把空串当"清空密钥"，`null` 才是不改 |
| 探测会改 base_url | `/validate` 回 `resolved_base_url`，后端保存时也用这个值（运行时直接拼 `/chat/completions`） |
| `model.options` 走 RPC 且有 1h 磁盘缓存 | 模型目录刚改过（如新增自定义端点）可能看不到，需要显式刷新 |
| 贵模型二次确认 | `confirm_required` 必须弹窗，确认后用 `confirm_expensive_model=true` 重发 |
| `terminal.read` 是 server→client 请求 | 由窗口应答，不是我们主动调用（见 [04-终端.md](04-终端.md)） |
| 块注释里写路径通配 | KDoc 写 `` `/api/profiles/*` `` 会开启**嵌套块注释**吞掉整个文件，编译器只报别的文件的 `Unresolved reference` |
