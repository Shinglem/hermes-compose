## 1. 模块策略：单 app 模块 + 两个旁路模块

**结论**：`composeApp` 承担全部业务，用**包**分层；只有满足下面判据的子系统才拆到 `modules/`。

| 判据（同时成立） | 说明 |
|---|---|
| ① 引入主模块其它代码完全不用到的重依赖 | 例如 Swing/AWT/PTY（终端）、渲染栈（markdown/highlights/mermaid） |
| ② 实现只落在单一平台 source set | 终端只有 desktop |
| ③ 有独立测试面（或明确为将来替换预留边界） | PTY/连接器可纯 JVM 测；渲染层是 v0.3 自研的替换点 |

已拆：

| 模块 | 形态 | 理由 |
|---|---|---|
| `modules/terminal` | `kotlin("jvm")` + Compose | BossTerm 裁剪版的宿主：PTY、渲染、读屏接口都锁在模块里（渲染实现见 `modules/terminal-bossterm`） |
| `modules/terminal-bossterm` | KMP `jvm("desktop")`（submodule，composite build） | BossTerm 的裁剪 fork：Compose Canvas 终端渲染 + pty4j + IME；宿主通过 `ai.rever.bossterm:compose-ui` 消费（ADR-054） |
| `modules/markdown-one` | KMP `jvm("desktop")`（submodule） | 解析 / 块路由 / 高亮 / 图表 / 公式全在库内，可直接发布到 Maven |

**不拆**：按 `feature/*` 再拆。本项目 1.8 万行规模下，包边界 + 依赖方向纪律足够；
拆分只解决"重依赖隔离"与"未来替换点"，不解决分层。

依赖方向：`composeApp → modules`，**反向禁止**。跨模块只用公开门面
（`TerminalHost`、`MarkdownText` / `MarkdownRenderer`）。

详见 ADR-044。

## 2. source set

```kotlin
kotlin {
    jvm("desktop")          // 只有桌面目标；target 名与 source set 名对应
}
```

| source set | 放什么 | 禁止放什么 |
|---|---|---|
| `commonMain` | **全部 UI、ViewModel、Repository、传输层、契约类型、偏好封装** | `java.nio` / `java.awt` / `System.*` / Swing |
| `desktopMain` | `main()`、`Window` 入口、PTY、外链编辑器、剪贴板、文件对话框、日志落盘、`Preferences` 实现 | 业务规则（否则将来加平台要重写） |
| `commonTest` | Repository / 状态机 / 解析器 / 格式化 | 依赖 AWT 的测试 |
| `desktopTest` | UI 测试（`runComposeUiTest`）、真实文件系统相关 | — |

> **纪律**：`commonMain` 一旦 import 到 `java.*` 或 `javax.*` 之外的桌面专有包，说明该能力应下沉到
> `desktopMain` 并由 `expect/actual` 暴露。反过来，`expect` 声明只放在 `commonMain`，
> 且**每个 target 必须有 `actual`**（只有一个 target 时也照写，为将来留位）。

### 2.1 唯一的 `expect/actual` 清单

| `expect`（commonMain） | `actual`（desktopMain） | 用途 |
|---|---|---|
| `fun openExternal(url: String)` | `Desktop.getDesktop().browse(URI)` | 外链、跳转 VSCode/IDEA |
| `fun openInEditor(path: String, command: String)` | 解析命令模板 → `ProcessBuilder` | 外链编辑器（ADR-005） |
| `expect class Clipboard` | AWT `Toolkit` | 文本 / 图片粘贴 |
| `expect class AppLogger` | 文件 + stderr | 日志落盘、设置页"打开日志目录" |
| `expect val appDataDir: String` | `%LOCALAPPDATA%\hermes-compose` | 配置 / 日志 / 缓存根 |
| `expect fun createPty(...)` | Pty4J | 终端（经 BossTerm 封装） |

其余一律**不写 `expect`**：保持 `commonMain` 可编译、可测试。

**命名规则**

- 文件名 = 主要声明名（`SessionListState.kt` 放 `SessionListState`）。
- `*Repository` 只碰数据，不 import `androidx.compose.*`。
- `*State` / `*ViewModel` 持有 `StateFlow`，不 import `androidx.compose.material3.*`（可 import `runtime`）。
- Composable 文件按"界面单元"命名（`MessageItem.kt`），一个文件一个公开 Composable。

## 4. 启动链路

```
desktopMain/Main.kt
  fun main() = application {
      val container = remember { DesktopContainer.build() }   // AppContainer 单例
      LaunchedEffect(Unit) { container.start() }              // 连接 + 启动期批量读
      Window(onCloseRequest = ::exitApplication, title = ProductInfo.DISPLAY_NAME, state = …) {
          App(container)
      }
  }

commonMain/App.kt
  @Composable fun App(container: AppContainer) {
      HermesTheme {
          CompositionLocalProvider(LocalAppContainer provides container) { AppShell() }
      }
  }
```

**硬规则**

- `GatewayClient` / `RestClient` **只在 `AppContainer` 里创建一次**（ADR：多窗口复用同一连接）。
- `Window` 里**不建连接**；`application { }` 作用域才是进程级。
- 连接启动放在 `LaunchedEffect`，且 `AppContainer.start()` 必须**幂等**（重连由 client 内部管理）。
- `App` 保持无参数化的可预览性：`AppShell` 通过 `LocalAppContainer` 取依赖，便于 `@Preview` 注入 fake。

## 5. 官方要求 → 本项目做法

| 官方要求 / 推荐 | 本项目做法 |
|---|---|
| Kotlin 2.0+ 必须单独应用 Compose Compiler 插件 | 根 `build.gradle.kts`：`alias(libs.plugins.compose.compiler) apply false`，模块内应用；插件版本与 Kotlin 一致 |
| 依赖统一走版本目录 | 全部版本只在 `gradle/libs.versions.toml`；模块内不写版本号；CMP 内部件用 `compose.*` DSL |
| 资源放 `src/commonMain/composeResources/{drawable,font,values,files}` | 文案进 `values/strings.xml`，用 `Res.string.*`；**禁止** `object Strings` 里堆中文（与 `AGENTS.md` §6 一致，采用官方资源机制） |
| `Res` 生成类需要 `compose.components.resources` 依赖 | `commonMain` 加 `implementation(compose.components.resources)` |
| Desktop 入口用 `application { Window { } }` | `desktopMain/Main.kt`，见 §4 |
| ViewModel 在多平台必须给 initializer（无反射） | 一律 `viewModel { SessionListViewModel(container.sessionRepository, …) }` |
| `viewModelScope` 依赖 `Dispatchers.Main.immediate`，desktop 默认没有 | `desktopMain` 加 `kotlinx-coroutines-swing`（**必须**，否则 ViewModel 协程不执行） |
| 桌面测试用 JUnit 也可用 `runComposeUiTest` | `commonTest` 用 `runComposeUiTest`；`desktopTest` 补目标依赖 |
| 打包用 `nativeDistributions` | MSI + Exe，见 §6 |
| 不在 Composable 里直接发请求 | 副作用走 `LaunchedEffect` + Repository（`AGENTS.md` §6） |

## 7. 常见坑（建工程时就会踩）

| 现象 | 原因 | 应对 |
|---|---|---|
| `jvm("desktop")` 后找不到 `desktopMain` | source set 名跟随 target 名 | 目录必须叫 `src/desktopMain`，不是 `jvmMain` |
| ViewModel 里 `viewModelScope` 协程不跑 | desktop 缺 `Dispatchers.Main.immediate` | 加 `kotlinx-coroutines-swing` 到 `desktopMain` |
| `viewModel()` 报 "no initializer" | common 代码无反射 | 一律传 initializer：`viewModel { XxxVm(deps) }` |
| `Res.string.xxx` 找不到 | 未加 `compose.components.resources` 或未同步 Gradle | 加依赖 + `./gradlew generateComposeResClass` |
| JitPack 依赖解析失败 | 未加 `maven("https://jitpack.io")` | 见 §6.1 |
| 中文乱码 / 编译警告 | 未统一 UTF-8 | `-Dfile.encoding=UTF-8`；文件存 UTF-8 无 BOM |
| MSI 打包缺 JRE | `nativeDistributions` 未含模块 | 需要时配置 `modules("java.instrument", …)`，先跑 `suggestRuntimeModules` |
| 打出的包启动即崩 | `mainClass` 类名错（`MainKt` 后缀） | 顶层 `main` 在 `Main.kt` ⇒ `dev.shinglem.hermes.MainKt` |
