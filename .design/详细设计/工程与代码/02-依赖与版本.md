### 1.1 终端的接入方式（不再是 Maven 坐标）

```kotlin
// settings.gradle.kts
includeBuild("modules/terminal-bossterm") {
    dependencySubstitution {
        substitute(module("ai.rever.bossterm:compose-ui")).using(project(":compose-ui"))
    }
}

// modules/terminal/build.gradle.kts
implementation("ai.rever.bossterm:compose-ui")   // 由 composite build 解析到 fork
```

- **不需要 JitPack**，**不需要 `packages.jetbrains.team`**：两个仓库都已从 `settings.gradle.kts` 删除。
- 克隆后必须 `git submodule update --init --recursive`，否则子模块目录是空的、配置阶段就报错。
- 可见性：`compose-ui` 对 `bossterm-core` 是 `implementation` → 宿主拿不到 `TerminalTextBuffer`，
  读屏接口只能在 fork 的 `compose-ui/TerminalFactory.kt` 上暴露。
- 许可：上游 LGPLv3 / Apache-2.0 双许可，**fork 按 Apache-2.0 使用**。

> **旧的「JediTerm + Pty4J」方案已作废**（ADR-040 → ADR-054）：Swing 渲染层无法参与 Compose
> 合成，`SwingPanel` 会盖住 Compose 弹层，IME 组合态也不可控。历史对比见 `04-构建环境与镜像.md` §7。

| Compose UI Test | `org.jetbrains.compose.ui:ui-test` | `1.12.2` | commonTest | 版本跟随 CMP |

## 2. 兼容性：三条必须同时成立

```
Kotlin 2.4.21
   ├─ Compose Compiler plugin 2.4.21        （= Kotlin 版本，强行对齐）
   ├─ Compose Multiplatform 1.12.2          （runtime / foundation / material3）
   └─ kotlinx-serialization plugin 2.4.21
```

### ✅ 已实测通过（2026-10-26，Gradle 9.8.0 + JDK 27 → 字节码 21）

```
:composeApp:compileKotlinDesktop   BUILD SUCCESSFUL（首次 5m54s，含 ≈870MB 依赖下载）
:composeApp:build                  BUILD SUCCESSFUL in 12s
:composeApp:compileKotlinDesktop + compileTestKotlinDesktop   通过
```

依赖树无 `FAILED`。解析结果与版本表的差异见 [`04-构建环境与镜像.md`](04-构建环境与镜像.md) §6
（`material3` → 1.9.0、`datetime` → `0.8.0-0.6.x-compat`）。

### 仍未验证的部分

- `:composeApp:run`（需 `Main.kt`，框架阶段无源码）
- `packageDistributionForCurrentOS`（MSI/Exe 打包）
- `-Phermes.terminal=true`（BossTerm 需 JitPack 现场构建，实测 90s 超时）
- `desktopTest` 实际执行（当前 `NO-SOURCE`）

### P0 第一个任务就是验证这组搭配（✅ 已完成）

| 检查 | 命令 | 通过标准 |
|---|---|---|
| 依赖可解析 | `./gradlew :composeApp:dependencies --configuration desktopRuntimeClasspath` | 无 `FAILED` |
| Compose 编译 | `./gradlew :composeApp:compileKotlinDesktop` | 无 `Compose Compiler` 版本不兼容报错 |
| 资源类生成 | `./gradlew :composeApp:generateComposeResClass` | 生成 `Res` |
| 桌面启动 | `./gradlew :composeApp:run` | 出现空窗口、无异常 |
| UI 测试可跑 | `./gradlew :composeApp:desktopTest` | 一个 `runComposeUiTest` 通过 |

**若 Compose Compiler 报与 runtime 不兼容**：按 CMP 1.12.2 官方兼容表回退 Kotlin（例如 2.3.x），
**不要**同时改 CMP 版本。回退记录进 [`../../草案/07-decisions.md`](../../草案/07-decisions.md)。

**若 lifecycle 2.11.0 与 CMP 1.12.2 冲突**：降到 `2.10.0`（官方 ViewModel 文档示例即此版本）。

## 4. 不引入（已决策，别再加回来）

| 库 | 原因 | 出处 |
|---|---|---|
| Koin / Metro / Hilt | 单窗口、依赖少；手工 `AppContainer` 足够 | ADR-013 |
| Decompose / Navigation 3 / navigation-compose | 单窗口两模式，无深栈；`ListDetailPaneScaffold` 已管 list-detail 导航。官方把它列为**可选**能力，不是必须 | ADR-013 |
| SQLDelight / Room | 只需少量 key-value | ADR-005 语境 + 02-selection §6 |
| react-query 类缓存框架 | `StateFlow` + Repository 手写失效 | 03-architecture §4.1 |
| AndroidX 全套 | 只取 `lifecycle-viewmodel-compose` 一件 | ADR-012 |
| Kermit（暂缓） | 先用 `AppLogger` 门面，需要结构化日志再评估 | 02-selection §6 |

## 6. 升级纪律

- **一次只升一个组件**，单独提交，提交信息写清"为什么升"。
- 升级前先跑 §2 的五项检查，升级后**再跑一遍**。
- CMP 与 Compose Compiler 版本**永远同步**；Kotlin 与 serialization plugin **永远同步**。
- 预览版（`-alpha` / `-beta` / `-rc`）不得进 `[versions]`，除非已写 ADR 并说明回退点。

## 7. Markdown 渲染层：现状与行为契约

**2026-10-31 已换实现（ADR-052）**：渲染由 `modules/markdown-one`（git submodule，Apache-2.0）提供。

**2026-10-31 又去掉了门面模块（ADR-053）**：`modules/ui-markdown` 已删除。它只做了三件事，
其中两件是死抽象（只有一个实现的 `MarkdownRenderer` 接口、纯转接的 `MarkdownText`），
第三件（`PaperColorScheme`）已迁入 `composeApp`。现在宿主直接依赖 `:modules:markdown-one`。

### 7.1 现在的接缝（只有一处）

| 位置 | 现状 |
|---|---|
| `composeApp/.../markdown/HermesMarkdown.kt` | `fun MarkdownText(...)`：**调用方唯一入口**。把 `options.ui.markdown_style` 翻译成 markdown-one 的 `MarkdownConfig`，并透传 `streaming` / `selectable` / `onLinkClick`；`MarkdownConfig` 用 `remember` 缓存 |
| `composeApp/.../markdown/PaperMarkdownTheme.kt` | 纸面 Markdown 主题：排版沿用 Outside Paper，**颜色取本项目的 paper 色板**（`AppPaletteContrastTest` 守对比度）。不直接用 markdown-one 的 `outsidePaperTheme` —— 它的正文 7.4:1、次要文字 3.0:1 偏淡 |
| `composeApp/.../ui/theme/AppPalette.kt` | 界面色板：paper / ocean / sage / plum / amber 的亮暗两套 + `toColorScheme()`，只替换 M3 的语义角色 |

已删除：`MikepenzMarkdownRenderer`、`MikepenzRender`、`CodeHighlight.kt`、`CodeHighlighter.kt`、
`DiagramRenderer.kt`、`MermaidDiagram.kt` 及其测试 —— 能力都在 markdown-one 里
（`builtin.code` / `builtin.mermaid` / `BlockAdapter` SPI）。

依赖面同步：`gradle/libs.versions.toml` 已删 `markdown*` / `highlights` / `mermaid*` 坐标，
`settings.gradle.kts` 已删只为 `build.raft.mermaid` 服务的 botiverse 仓库。

### 7.2 要改渲染行为时去哪

| 想做 | 去改 |
|---|---|
| 换某类块的渲染方式 | 在 markdown-one 里加/换 `BlockAdapter`（见其 `docs/adapters.md`） |
| 换主题 / 间距 / 字号 | `MarkdownConfig.theme`（`HermesMarkdown.kt` 里按 `options.ui.markdown_style` 选：material → `markdownMaterialTheme()`；paper → 宿主 `paperMarkdownTheme()`） |
| 大块限高滚动缩放 | `MarkdownConfig.viewport`（`BlockViewportConfig`） |
| 数学公式排版（ratex） | `modules/markdown-one` 的 `builtin/DesktopMathAdapter` + `InlineMath.desktop.kt`（native dll 走 `ratex-native-windows-x86-64`） |
| 原始 HTML（原生渲染） | `modules/markdown-one` 的 `builtin/HtmlNativeAdapter` + `parse/HtmlSanitizer`（ksoup + GitHub 白名单）；JCEF 回退已于 v0.4.1 移除，见 [`11-JCEF集成.md`](11-JCEF集成.md) |
| 流式栅栏补齐 | 已在 markdown-one 的解析层（`parse/CodeFences.kt`），不要再在本地实现一份 |

### 7.3 行为契约（仍然是验收口径）

| # | 契约 | 判据 |
|---|---|---|
| M1 | **流式**：`streaming = true` 时未闭合代码栅栏不能变普通段落 | 对应验收 R4（`05-acceptance.md`）：边打 ``` 边看，始终显示为代码块骨架，不闪烁不抖动 |
| M2 | **流式不渲染图表** | 流式中 ` ```mermaid ` 只显示「图表生成中…」占位，完成后才排版（适配器读 `LocalIsStreaming` 自己降级） |
| M3 | 代码块：语法高亮 + 横向滚动 + 复制按钮；>8000 字符不染色 | 长文件不卡；复制按钮拿到的是原文（`maxSyncHighlightLength`） |
| M4 | 表格 / 标题 / 列表 / 引用 / 行内代码 / 链接 正常 | `MarkdownRenderTest` 钉住关键块；其余人工比对 |
| M5 | 图片走 Coil 加载，失败有占位 | 断网时不留白框 |
| M6 | 数学公式**正常渲染**（块级 + 行内）；内嵌 HTML 按源码/容器剥壳渲染（不崩） | 硬约束 8；公式走 `ratex`，HTML 走原生渲染 |
| M7 | 不引入跨消息选择能力（选区由 markdown-one 在每条消息内提供一层 `SelectionContainer`） | 硬约束 6 |
| M8 | 500 条消息的会话滚动不卡（P1 门槛） | `05-acceptance.md` P1 的滚动项 |
