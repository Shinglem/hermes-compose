# 07 · 提权与自启动（管理员权限 + 开机自启不弹 UAC）

> 回答两个互相牵制的问题：**客户端可以以管理员身份运行**（后端才能操作 elevated 窗口），
> **开机自启时不能弹 UAC**。
> 目录与配置分工见 [`05-打包与配置.md`](05-打包与配置.md)，后端进程规格见
> [`06-本地后端与双模式.md`](06-本地后端与双模式.md)。
>
> 状态：**P1 + P2 + P3 已实现（2026-10-29）** —— `app.elevate`、`runas` 提权重启、状态栏「普通权限」
> 提示（§10）；`app.autostart` 计划任务自启动（§11）；失效任务清理与端到端验证（§12）。
> 只剩 V5（注销重登）与 T10/T3（托盘图标）两项**用户明确决定暂不做**。
> 本文所有"实测"来自本机 `<机器名>\<用户名>` / Windows 11 专业工作站版，其余结论标注为"待实测"。

## 1. 目标与不变量

| # | 目标 / 不变量 |
|---|---|
| E1 | 客户端**可以**以管理员身份运行；`local` 后端的 `serve` / `dashboard` 跟随继承（不提权时也能跑） |
| E2 | 开机自启（登录触发）**绝不弹 UAC**，直接进托盘（`--silent`） |
| E3 | 默认**不提权**：不勾开关时行为与现在完全一致，普通权限、无额外系统对象 |
| E4 | 提权是**可配置**的，不改 exe 的任何字节（复用 `packaging/launcher/` 里入库的那两个 exe） |
| E5 | 用户的 UAC 拒绝不能把程序卡死：拒绝后以普通权限继续 |
| E6 | 不碰别人的 Hermes：不删除、不修改、不复用 `HermesDashboard` / `Hermes_Gateway_*` / `Hermes-Netcatty-*` 这类既有任务 |
| E7 | 便携包换路径后自启动仍指向**当前**这份安装 |
| E8 | 任何系统级写入（计划任务）都可一键撤销，撤销后系统里不留残迹 |

### 1.1 已确认的取舍（2026-10-29）

| 决策 | 结论 | 备注 |
|---|---|---|
| 日常双击要不要也免 UAC | **不要**。双击照常弹 UAC，接受 | 不做"走计划任务的启动快捷方式"那套 |
| 提权范围 | **整包提权**（客户端 + 后端同一管理员令牌） | 理由见 §2.1（UIPI） |
| 后端由谁拉起 | **客户端 spawn**，计划任务只启动客户端 | 后端的 stdout 仍由客户端转写日志（`08` §7 起补充 `startup.log`） |
| 单实例 | **纳入本期**（先做单实例，再做提权与自启动） | 独立成篇：[`08-单实例与启动时序.md`](08-单实例与启动时序.md) |

## 2. 为什么只有"计划任务"这条路

四条常见做法，只有一条同时满足 E1 + E2：

| 做法 | 管理员权限 | 登录自启弹 UAC | 可配置 | 结论 |
|---|---|---|---|---|
| exe 内嵌 manifest `requestedExecutionLevel=requireAdministrator` | ✅ | ❌ **必弹**（登录时也弹） | ❌ 两套 exe 才行 | ✗ |
| 注册表 `HKCU\...\Run` + `RUNASADMIN` 兼容性标记 | ✅ | ❌ **必弹** | 半 | ✗ |
| 注册表 `HKCU\...\Run`，普通权限 | ❌ | ✅ 不弹 | ✅ | 权限不足，✗ |
| **计划任务 `ONLOGON` + `RunLevel=HighestAvailable`** | ✅ | ✅ **不弹** | ✅ | ✔ 唯一可行 |

原因：登录时由 **Task Scheduler 服务**创建进程，该服务本身有特权，且任务已声明"以最高权限运行"，
所以不会走 `consent.exe`（UAC 提示）。而 manifest / Run 键都要经过用户态加载器的提权路径。

**官方 Electron 版 Hermes 也是这条路**（本机实测，只读查询）：

```
HermesDashboard              LogonTrigger  wscript.exe //B //Nologo ...\run-dashboard.vbs
Hermes_Gateway_92881c26      LogonTrigger  wscript.exe //B //Nologo ...\Hermes_Gateway_92881c26.vbs
Hermes-Netcatty-Launch       （无触发器字段）  C:\app\Netcatty\Netcatty.exe     ← 不是 Hermes 的
```

前两个是官方 Hermes 的登录自启任务，`UserId` 是当前用户、`LogonTrigger` 触发 ——
这是"不弹 UAC 的登录自启"的现成样板（它们用 `wscript` 包一层是为了消掉 cmd 黑框；
我们的启动器是 GUI 子系统，不需要这一层）。

第三条 `Hermes-Netcatty-Launch` 指向 `C:\app\Netcatty\Netcatty.exe` —— **名字带 Hermes 前缀但与 Hermes 无关**。
它正好证明 §3.5 那条纪律：**按名字前缀批量操作任务是会误伤的**。

### 2.1 为什么整包提权，而不是只提权后端

Windows 的 **UIPI**：普通权限进程无法向 elevated 窗口投递输入与消息（`computer_use` 模拟键鼠时
被静默丢弃，没有任何错误码）。所以只要目标窗口是管理员进程，非提权后端就"看不见"它。

链路因此只有一条：客户端提权 → 子进程继承管理员令牌 → `serve` / `dashboard` 自然也是管理员。
反过来做（普通客户端 + 提权后端）要么每次启动弹一次 UAC，要么把后端注册成服务（session 0，无 UI），
代价远大于收益。

## 3. 设计

### 3.1 配置项（都在 `config.json`，改完重启生效）

| 键 | 值 | 默认 | 含义 |
|---|---|---|---|
| `app.elevate` | `never` / `ask` | `never` | `ask`：启动时若未提权，用 `runas` 重新拉起自己（用户可拒绝） |
| `app.autostart` | `off` / `task` | `off` | `task`：维护一个登录触发的计划任务（最高权限、带 `--silent`） |

两项都进设置页（`SettingsCatalog`），`scope = RESTART`，写 `config_custom.json`。

**为什么 `app.autostart` 也放 `config.json` 而不是 `options.json`**：它的生效载体是系统里的计划任务，
切换动作需要管理员权限（§4.2 实测：非管理员连最低权限任务都建不了）。这类"改了就动操作系统"的开关
不该在 `options.json` 里做成热更新语义 —— 用户看不到"为什么勾了没反应"。

### 3.2 模块与文件

| 文件 | 职责 |
|---|---|
| `core/app/Elevation.kt`（commonMain） | 接口：`isElevated()` / `relaunchElevated(): Boolean` |
| `desktopMain/core/app/Elevation.desktop.kt` | FFM 实现：`OpenProcessToken` + `GetTokenInformation(TokenElevation)` / `ShellExecuteExW("runas")` |
| `core/app/Autostart.kt`（commonMain） | 接口：`state(): AutostartState` / `install(exePath)` / `remove()` |
| `desktopMain/core/app/ScheduledAutostart.kt` | `schtasks /Create /XML` 与 `/Delete`；任务定义生成与对账 |
| `desktopMain/core/app/WindowsCommandLine.kt` | **已实现**：取当前进程完整命令行（提权重启复用同一套还原逻辑） |
| `feature/settings/` | 两个开关 + 状态回显（"已启用 / 需管理员权限"） |

`AutostartState` 三态：`DISABLED`（任务不存在）/ `ENABLED`（存在且指向当前 exe 与参数）/ `STALE`（存在但指向旧路径）。

### 3.3 启动时序

**权威顺序在 [`08-单实例与启动时序.md`](08-单实例与启动时序.md) §5** —— 单实例判断、配置解析、
提权重启三者的先后顺序互相牵制（顺序错了会活锁或"先弹 UAC 才被告知已有一份"），只在那里维护一份。

本篇只约束提权这一环：

| 约束 | 原因 |
|---|---|
| 提权发生在**单实例探测之后、`CreateMutex` 之前** | 探测阶段不持有任何对象，`runas` 重启不会让新进程误判"已有实例"（`08` §5 步骤 1/3/4） |
| 不需要 `--elevated-retry` 之类的内部参数 | 提权重启沿用完整命令行；重启后的进程 `isElevated() == true`，不会再进这个分支 |
| 用户拒绝 UAC 时**继续以普通权限运行** | 记一行 WARN 到 `startup.log`，并在状态栏显示「普通权限」；若直接退出，用户会以为程序坏了。配置仍是 `ask`，下次启动还会再问 |

### 3.4 计划任务定义

用 `/XML` 导入而不是 `/TR`（`schtasks /TR` 的引号规则极易写错，路径带空格就炸）：

```xml
<?xml version="1.0" encoding="UTF-16"?>
<Task version="1.4" xmlns="http://schemas.microsoft.com/windows/2004/02/mit/task">
  <RegistrationInfo>
    <Description>Hermes desktop client · 登录时以最高权限启动（无 UAC）</Description>
    <!-- URI 里写真实任务名（= HermesCompose-<home 路径的 sha256 前 8 位>），下例是 a1b2c3d4 -->
    <URI>\HermesCompose-a1b2c3d4</URI>
  </RegistrationInfo>
  <Triggers>
    <LogonTrigger>
      <Enabled>true</Enabled>
      <UserId><机器名>\<用户名></UserId>
      <!-- 登录瞬间 explorer/托盘还没就绪，立刻启动会导致托盘图标加不上 -->
      <Delay>PT20S</Delay>
    </LogonTrigger>
  </Triggers>
  <Principals>
    <Principal id="Author">
      <UserId><机器名>\<用户名></UserId>
      <LogonType>InteractiveToken</LogonType>
      <RunLevel>HighestAvailable</RunLevel>
    </Principal>
  </Principals>
  <Settings>
    <MultipleInstancesPolicy>IgnoreNew</MultipleInstancesPolicy>
    <DisallowStartIfOnBatteries>false</DisallowStartIfOnBatteries>
    <StopIfGoingOnBatteries>false</StopIfGoingOnBatteries>
    <AllowHardTerminate>true</AllowHardTerminate>
    <StartWhenAvailable>true</StartWhenAvailable>
    <ExecutionTimeLimit>PT0S</ExecutionTimeLimit>
    <Enabled>true</Enabled>
  </Settings>
  <Actions Context="Author">
    <Exec>
      <Command>D:\Hermes\Hermes.exe</Command>
      <Arguments>--silent</Arguments>
      <WorkingDirectory>D:\Hermes</WorkingDirectory>
    </Exec>
  </Actions>
</Task>
```

| 字段 | 为什么是它 |
|---|---|
| `RunLevel=HighestAvailable` | E1 的来源。**不要** `RequireHighest`（用户不是管理员时会直接失败） |
| `LogonType=InteractiveToken` | 在**当前登录会话**里启动 → 有 UI、有托盘；`S4U`/`ServiceAccount` 会落到无 UI 的会话 |
| `Trigger: LogonTrigger` + `UserId` | 只在该用户登录时触发，不用 `BootTrigger`（那时桌面还没起来） |
| `Delay=PT20S` | 登录瞬间 explorer 与托盘区可能尚未就绪，立刻启动会有"进程起来了但托盘没图标"。`StartWhenAvailable=true` 保证错过也能补跑 |
| `MultipleInstancesPolicy=IgnoreNew` | 只在"由任务重复触发"时生效；**用户手动双击与自启并存要靠单实例解决**（`08`） |
| `ExecutionTimeLimit=PT0S` | 默认 `PT72H`（3 天）会到点强杀，必须显式取消 |
| `DisallowStartIfOnBatteries=false` | 笔记本上不因为省电策略跳过自启 |
| `Arguments=--silent` | E2：登录后进托盘，不弹窗（`--silent` 已在 `Main.kt` 实现）。对账时**也校验这个参数**——只比 `<Command>` 的话，早期版本写下的无参任务会被当成健康（§3.9） |

> XML 文件必须 **UTF-16 编码 + 带 BOM**，`schtasks /XML` 对编码敏感；用 UTF-8 会报
> "任务 XML 包含错误格式"（待实测确认本机行为）。

### 3.5 任务命名与多份安装隔离

```
HermesCompose-<sha256(home 绝对路径) 前 8 位小写十六进制>
```

| 理由 | 说明 |
|---|---|
| 不能只叫 `Hermes` | 机器上已有官方的 `HermesDashboard` / `Hermes_Gateway_*`，撞名会互相覆盖 |
| 要区分多份便携包 | 解压两份到不同目录时各自的自启动要能独立开关（home 不同 → 名字不同） |
| 便于反查 | 设置页把任务名显示出来，用户能在任务计划程序里自己找到并删掉 |

**绝不**按前缀模糊匹配删除任务：本机 `Hermes-Netcatty-Launch` 指向的是
`C:\app\Netcatty\Netcatty.exe`，`Where Name -like "Hermes*"` 会把它一起删掉。
只对**算出来的那一个确切名字**做 `Query` / `Create` / `Delete`。

### 3.6 对账（`reconcile`）

每次启动跑一次只读检查，不需要管理员：

| 实际状态 | `app.autostart` | 动作 |
|---|---|---|
| 任务不存在 | `off` | 无 |
| 任务不存在 | `task` | 未提权 → 设置页标黄「需管理员权限后生效」；已提权 → 自动创建 |
| 任务存在且 `Command` == 当前 exe **且 `Arguments` 含 `--silent`** | `task` | 无（HEALTHY） |
| 任务存在但 `Command` != 当前 exe，或 `Arguments` 缺 `--silent` | `task` | 已提权 → 覆盖为当前路径 + `--silent`；未提权 → 标 `STALE` 并提示 |
| 同一 exe 存在**别的**本产品任务（早期固定名 `HermesCompose`） | `task` / `off` | 已提权 → 删掉多余的（当前任务写成功之后才删，见 §3.9） |
| 任务存在 | `off` | 已提权 → 删除；未提权 → 提示"配置已关闭，但系统里还有自启任务" |

读取用 `schtasks /Query /TN <name> /XML`（非管理员可读），解析 `<Command>` / `<Arguments>` 两个字段即可，
不用 XML 反序列化框架（字符串取值就够，避免为一个字段引入解析器）。

### 3.7 设置页交互

| 用户动作 | 已提权 | 未提权 |
|---|---|---|
| 打开「以管理员身份运行」 | 保存即可（重启后生效） | 保存 + 提示"重启后生效；届时会弹一次 UAC" |
| 打开「开机自启」 | 立即写计划任务，显示任务名 | 提示"需要管理员权限"→ 提供「提权重启并启用」（走 `runas`，重启后由 §3.6 自动补建） |
| 关闭「开机自启」 | 立即删任务 | 提示"需要管理员权限才能删除自启任务" |

"提权重启并启用"这个动作要**先落盘再重启**（把 `app.autostart=task` 写进 `config_custom.json`），
这样重启后的进程在 `reconcile` 阶段自然把它补建出来 —— 不需要跨进程传"待办事项"。

### 3.8 便携包移动后残留的旧任务

任务名带 `<home>` 哈希，所以把目录从 `D:\Hermes` 挪到 `E:\Hermes` 之后：

- 新位置启动 → 算出**新名字** → 建任务
- 旧名字的任务还指着 `D:\Hermes\Hermes.exe`（已不存在）→ 每次登录都会失败一次

处理方式（**只读列出 + 逐条确认删除**，绝不按前缀批量）：

| 步骤 | 做法 |
|---|---|
| 扫描 | `schtasks /Query /FO LIST /V` 列出全部任务，只挑出：`Description` 以本产品固定前缀开头 **且** `Command` 路径不存在 |
| 展示 | 设置页列出「任务名 · 指向的路径 · 该路径不存在」，用户勾选后删除 |
| 删除 | `schtasks /Delete /TN <确切名字> /F`（需要管理员） |
| 不做 | 不猜测、不批量、不删 `Command` 仍存在的任务（可能是另一份**正在用**的安装） |

本机就有一个反例：`Hermes-Netcatty-Launch` 指向 `C:\app\Netcatty\Netcatty.exe` ——
名字带 `Hermes` 前缀但与本产品无关，任何"按前缀删"的实现都会误伤它。

### 3.9 同一份安装只该有一条自启任务

任务名从早期版本的**固定名** `HermesCompose` 演变成 `HermesCompose-<home hash>`，升级后算出的
名字与系统里那条老任务对不上，于是**两条同时触发**：

| 顺序 | 任务 | 结果 |
|---|---|---|
| 1 | 老任务 `HermesCompose`（**没有** `--silent`） | 拉起一个**带主窗口**的实例，还会白弹一次 UAC |
| 2 | 新任务 `HermesCompose-<hash>`（`--silent`，`Delay=PT20S`） | 晚 20 秒起来，被单实例挡掉 → 静默退出 |

用户看到的就是"开机自启会弹窗"，而且老任务永远不会被清理（截图里的任务描述为空、`Task version="1.3"`）。

处理规则（`parseDuplicateTasks`，只在**已提权**时执行删除）：

| 条件 | 动作 |
|---|---|
| 名字匹配 `^HermesCompose(-[0-9a-f]{8})?$` | 候选 |
| 名字 == 当前任务 | 跳过（那是自己） |
| `<Command>` 与当前启动器**同一路径** | 删除（同一份安装的冗余任务） |
| `<Command>` 指向别处 | 不碰（可能是另一份正在用的安装） |
| 其它名字（`Hermes-Netcatty-Launch` / `HermesDashboard`） | 一律忽略 |

顺序要求：**先确保当前任务写成功，再删冗余任务**。反过来的话，`/Create` 失败会让这份安装
彻底失去自启（旧任务已删、新任务没写成）。

> 升级后**第一次**登录仍可能弹一次窗口：那一刻旧任务还在，是它把进程拉起来的；该进程自己
> 以管理员跑完 `reconcile` 后就会把旧任务删掉，之后每次登录都是直接进托盘。

## 4. 实现要点

### 4.1 提权检测与提权重启（FFM，零依赖）

| 用途 | API | 说明 |
|---|---|---|
| 是否管理员 | `OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY)` + `GetTokenInformation(TokenElevation)` | 比 `IsUserAnAdmin()` 准确（后者受 UAC 虚拟化影响，且需要 COM 初始化） |
| 提权重启 | `ShellExecuteExW`，`lpVerb = "runas"`，`lpFile` = 当前 exe，`lpParameters` = 当前参数 | 等价于资源管理器里的"以管理员身份运行" |
| 命令行还原 | **复用 `WindowsCommandLine.current()`** | 已实现并有测试；`ProcessHandle.Info.arguments()` 在 Windows 上可能为空（见 `DesktopAppRestarter` 注释） |

```kotlin
// 结构与 SHELLEXECUTEINFOW：cbSize + fMask + hwnd + lpVerb + lpFile + lpParameters + lpDirectory + nShow + ...
// 只用前 9 个字段有意义；fMask = SEE_MASK_NOCLOSEPROCESS(0x40) | SEE_MASK_NOASYNC(0x100)
// 返回 FALSE 且 GetLastError() == ERROR_CANCELLED(1223) → 用户点了"否"
```

`ERROR_CANCELLED` 是**唯一**要吞掉的错误码：它代表用户明确拒绝，不是故障（E5）。

### 4.2 计划任务的增删（`schtasks`，无新依赖）

| 操作 | 命令 | 需要的权限 |
|---|---|---|
| 读 | `schtasks /Query /TN <name> /XML` | 当前用户（实测可读） |
| 建 | `schtasks /Create /TN <name> /XML <file> /F` | **管理员** |
| 删 | `schtasks /Delete /TN <name> /F` | **管理员** |

**实测（2026-10-29，非管理员）**：

```
schtasks /Create ... /RL HIGHEST  → ERROR: Access is denied.  (exit=1)
schtasks /Create ... /RL LIMITED  → ERROR: Access is denied.  (exit=1)
```

即：**任何**计划任务的创建都需要提权，与 `RunLevel` 无关。这直接决定了 §3.7 的交互
（开关自启动必须先提权）以及"未提权时只提示、不静默失败"的行为。

不用 PowerShell `Register-ScheduledTask`：那要额外起一个 pwsh 进程（慢 1–2 s）且要处理执行策略，
`schtasks.exe` 系统自带、参数稳定。

### 4.3 提权后需要复查的既有假设

| 假设 | 提权后是否仍成立 | 依据 |
|---|---|---|
| `<home>` 定位 | ✅ | 由 `app\hermes-desktop-compose.cfg` 的 `-Dhdc.home=$ROOTDIR` 传入，与 `user.dir` 无关 |
| 工作目录 | ⚠️ 计划任务的 `WorkingDirectory` 已显式写入；`user.dir` 不能作为任何路径基准 | 现有代码只用 `user.dir` 作开发态 fallback |
| 日志目录 | ✅ | `app.log.dir` 相对 `<home>`/数据目录 |
| Job Object 兜底 | ✅ | 由新进程自己 `CreateJobObject`，与是否提权无关 |
| Compose 渲染 | ✅ | 提权不影响 Skiko（同一用户会话） |
| 后端 `HERMES_HOME` | ✅ | 显式传入，且落在便携目录内 |

> **待实测**：以计划任务（`RunLevel=HighestAvailable`）启动时 `user.dir` 实际值（预期是
> `WorkingDirectory` 或 `C:\Windows\System32`），以及托盘图标在 elevated 会话里的显示。

## 5. 坑（现象 / 原因 / 应对）

| # | 现象 | 原因 | 应对 |
|---|---|---|---|
| 1 | 改了 exe manifest 后每次登录都弹 UAC | `requireAdministrator` 的提权发生在加载器路径 | 不改 manifest，走计划任务（§2） |
| 2 | `schtasks /TR "\"C:\a b\app.exe\" --silent"` 报参数错误 | `/TR` 是一个字符串参数，内层引号被 cmd/schtasks 二次解析 | 改用 `/XML`，`<Command>` 与 `<Arguments>` 分开 |
| 3 | 任务建好但登录后什么都没出现 | 用了 `/RU SYSTEM` 或 `LogonType=S4U` → 进程在无 UI 的会话里 | `InteractiveToken` + 当前用户 |
| 4 | 登录后进程几分钟后被杀 | 计划任务默认 `ExecutionTimeLimit=PT3D` | 显式写 `PT0S` |
| 5 | 笔记本电池供电时不自启 | 默认 `DisallowStartIfOnBatteries=true` | 显式 `false` |
| 6 | 便携包换目录后自启仍开旧程序 | 任务里存的是绝对路径 | 启动时 `reconcile` 比对 `Command`（§3.6） |
| 7 | 用户拒绝 UAC 后程序起不来 | 把 `ERROR_CANCELLED` 当成失败处理 | 只记 WARN，继续以普通权限运行 |
| 8 | 提权后设置在 `config_custom.json` 里"丢了" | 误用了 `%APPDATA%` 之类的漫游路径 | 一切路径以 `<home>` 为基准（`05` §3.1 已定） |
| 9 | 卸载/换机器后系统里留下自启任务 | 只改配置不删任务 | 设置页关闭 + 文档给出 `schtasks /Delete /TN <name>` |
| 10 | 提权进程无法拖拽文件（资源管理器是普通权限，反向 UIPI） | 高完整性进程不能接收低完整性进程的拖放 | 已知限制，文档记录；不为此降权（E1 优先） |
| 11 | 强杀客户端后后端**没被 Job 杀掉**（看起来像 Job 没生效） | `CreateJobObjectW` 传了可继承的 `SECURITY_ATTRIBUTES` → 后端子进程自己攥着 Job 句柄，最后一个句柄永不关闭 | **保持 `lpJobAttributes = NULL`**（句柄不可继承）；这条写进 `15-关停安全规格.md` 与代码注释，改之前先想清楚 |
| 12 | 登录自启后"什么都没出现"，日志里也查不到 | 配置解析失败时只 `System.err.println`，而 `javaw` 没有控制台 | `startup.log`（不依赖 logback 的极早期日志），见 [`08`](08-单实例与启动时序.md) §7。实测：静默启动 + 坏配置时进程 0 个、日志文件一字节未变 |
| 13 | 计划任务触发时把用户正在操作的窗口抢到前台 | 触发时带了 `--silent`，但仍走"已有实例就唤醒"的分支 | 单实例的唤醒语义按 `--silent` 分流（`08` §5 步骤 1） |
| 14 | 用 WMI 查提权实例的命令行/环境全是空 | 非管理员读不到 elevated 进程的 `Win32_Process.CommandLine`（系统保护） | 排障看 `startup.log` 与 `desktop.log`（自己写的文件不受影响），别指望 `Get-CimInstance` |
| 15 | 提权后"我的文档/桌面"路径拿到的是 `C:\Windows\system32\config\systemprofile` | 只在以 `SYSTEM` 身份运行时才发生（`/RU SYSTEM`）；同一用户提权不会 | 只用 `HighestAvailable` + `InteractiveToken`，不碰 `/RU SYSTEM` |
| 16 | 升级后开机自启照样弹主窗口（日志里 `silent=false`、参数 `(none)`） | 系统里还留着早期版本的固定名任务 `HermesCompose`——没有 `<Arguments>--silent</Arguments>`，且对账只比 `<Command>` 所以永不重写 | 对账同时校验 `<Arguments>`；`parseDuplicateTasks` 清掉**同一 exe** 上的冗余任务（§3.9）。实测：真实全量任务 XML 下识别出 `HermesCompose`，当前任务与别家任务都不动 |

### 11.2 两个实现细节

- **XML 必须 UTF-16LE + BOM**（`0xFF 0xFE` 前缀）。用 UTF-8 写会报"任务 XML 包含错误格式"。
  这条现在已由实测确认（T1 关闭）。
- **读回任务定义用 GBK 解码**：`schtasks /Query /XML` 的输出是控制台编码（中文系统 CP936）。
  GBK 解 ASCII 也是对的，所以非中文系统上同样安全。解析失败一律当作"不匹配"——
  那只会让已提权时多写一次任务，坏不到"用着旧路径还自以为没问题"。

### 11.3 实测

| 场景 | 结果 |
|---|---|
| `elevate=ask` + `autostart=task`，UAC 点"是" | `startup.log`：`autostart task=HermesCompose-b4437198 installed=true pending=false configured=TASK` |

| 配置改 `autostart=off` 后由任务启动一次（V8） | `autostart … installed=false`，`schtasks /Query` 返回"任务不存在" —— 自动删除生效 |

### 11.4 还没验证

- **V5 的"注销再登录"**：`schtasks /Run` 已经证明任务本身能拉起 elevated + silent 的实例，
  剩下的只是"LogonTrigger 会不会在登录时触发"—— 这一步需要真的注销一次，留给人工
- **T10（托盘图标）**：`--silent` 起的实例在托盘区没直接看到图标，Windows 11 默认把新图标
  折叠进 `^`。是否被折叠而非"没显示"，需要点开 `^` 面板确认
- **T3（elevated 会话里的托盘/通知）**：与 T10 一起确认

### 11.5 reconcile 的两种模式（与设计稿的差异）

设计稿 §3.6 列了 `STALE` 状态（任务存在但指向旧 exe）。实现里把它简化成：

| 实际情形 | 处理 |
|---|---|
| 已提权 + 配置 `task` + 任务不健康（缺失 / 指向旧路径 / 缺 `--silent`） | **直接 `/Create /F` 重写**（幂等） |
| 已提权 + 配置 `off` + 任务存在 | `/Delete` |
| 未提权 | 只读查询，`pending=true` 交给 UI 提示 |
| 配置 `off` + 任务存在 + 未提权 | `pending=true`，提示"以管理员运行后会自动删除" |

不再单独区分 `STALE`：既然重写是幂等的，"是否 stale"这个中间态对用户没有额外信息量。

## 12. P3 / P4 落地情况（2026-10-29）

### 12.1 失效自启任务清理（§3.8 落地）

便携包换盘符后旧任务仍指向老路径。实现：

| 步骤 | 做法 |
|---|---|
| 收集 | `schtasks /Query /XML`（不带 `/TN`）一次拿到**全部**任务定义（本机 283 个、约 1 MB），比逐个查询快一个数量级 |
| 筛选 | `<URI>` 去前导 `\` 后**完全匹配** `^HermesCompose-[0-9a-f]{8}$`；排除当前任务名；`<Command>` 指向的文件必须**不存在** |
| 展示 | 设置页「开机自启」下方逐条列出 `任务名 → 路径`，每条一个「删除」按钮；未提权时按钮禁用并说明原因 |
| 删除 | `schtasks /Delete /TN <确切名字> /F`，成功后才从列表移除 |

**连多选都不做**：本机 `Hermes-Netcatty-Launch` 指向 `C:\app\Netcatty\Netcatty.exe` —— 名字带 `Hermes`
前缀但与本产品无关，任何"批量"都可能有天误伤。

解析逻辑抽成 `parseOrphans(xml, currentTaskName, exists)` 纯函数，6 条单测覆盖：
只认本产品名字、排除当前任务、路径仍存在的不列为失效、前缀相似的一律忽略（含 `HermesCompose-tooshort`、
`HermesCompose-zzzzzzzz` 这种"像但不合规"的名字）。

> 端到端（真造一个"换了盘符 + 旧任务残留"的场景）没有做：造它需要"不同 home hash 的任务 + 该 exe 已不存在"，
> 代价远高于价值。解析逻辑有单测，删除走的是与 `/Create` 同一条 `schtasks` 通道。

### 12.2 端到端（P4）

| 项 | 结果 |
|---|---|
| **T9：elevated 下强杀** | 提权实例（pid 38356）被 `Stop-Process -Force` → **2 秒内**后端两个 python 进程（serve 37144 / dashboard 35940）消失。Job Object 与是否提权无关 |
| V9：官方任务不被修改 | `HermesDashboard` / `Hermes_Gateway_92881c26` / `Hermes-Netcatty-Launch` 全程原样 |
| V10：撤销后无残留 | 清掉 `config_custom.json` + 关掉自启动后：无 `HermesCompose-*` 任务、无 `HKCU\...\Run` 项、无残留进程 |
| 孤儿扫描不误报 | 正常运行（无失效任务）时 `orphans` 为空，`startup.log` 无 `WARN autostart 发现...` |

### 12.3 明确不做（用户决定）

- **V5 注销重登**：`schtasks /Run` 已经证明任务能拉起 elevated + `--silent` 的实例，登录触发器是同一机制
- **T10 / T3 托盘图标**：`--silent` 起的实例在托盘区没直接看到图标，Windows 11 默认把新图标折叠进 `^`；
  是"被折叠"还是"没显示"留给用户点开面板确认

### 12.4 剩余风险

| 风险 | 说明 |
|---|---|
| 提权实例与非提权实例的 `startup.log` 并发写 | 都是"一次 append 一行"，Windows 上小块 append 是原子的；不会互相截断 |
| 计划任务与手动启动的极端竞态 | `MultipleInstancesPolicy=IgnoreNew` 管任务重复触发，跨来源靠单实例（`08`）兜底 |
| 用户把便携包挪到另一个盘后第一次启动 | 任务名变了 → 新任务会建（需管理员），旧任务进"失效列表"等用户确认删除 |
