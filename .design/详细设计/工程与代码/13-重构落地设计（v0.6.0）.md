## 2. 分层与边界（照抄即可执行的规则）

### 2.1 四条 import 规则

| # | 规则 | 理由 |
|---|---|---|
| R1 | `component/` 与 `domain/` **不得** import `androidx.compose.*` | Decompose 的核心承诺：业务逻辑可纯 JVM 单测 |
| R2 | `core/` 与 `domain/` **不得** import `dev.shinglem.hermes.{component,ui,shell}` | 依赖单向向下 |
| R3 | `ui/` **不得** import `dev.shinglem.hermes.data` | UI 只认识 Component 与 domain 模型 |
| R4 | `dev.nucleusframework.*` **只允许** 出现在 `shell/` | Nucleus 可替换，代价锁在一层 |

`R4` 的实测例外：`di/Modules.kt` 若需引用 `NucleusTray` 类型，允许 —— 架构测试放行
`shell/` 与 `di/` 两个前缀。

```kotlin
class DefaultChatComponent(
```

```kotlin
// component/<域>/store/<域>Reducer.kt —— 纯函数，无框架
internal class ChatReducer : Reducer<ChatState, ChatResult> {
    override fun ChatState.reduce(result: ChatResult): ChatState = when (result) {
        is ChatResult.Delta -> copy(streaming = streaming.appendAnswer(result.text))
        is ChatResult.Reasoning -> copy(streaming = streaming.appendReasoning(result.text))
        is ChatResult.ToolStarted -> copy(streaming = streaming.startTool(result.id, result.name))
        is ChatResult.ToolFinished -> copy(streaming = streaming.finishTool(result.id, result.ok))
        is ChatResult.Snapshot -> copy(items = result.items)
        is ChatResult.Failed -> copy(error = result.error.toNotice())
    }
}
```

### 3.2 Executor（唯一 place 做 suspend 与取消）

```kotlin
internal class ChatExecutor(
    private val repository: ChatRepository,
    private val runtime: SessionRuntimeStore,
    private val key: SessionKey,
    executorContext: CoroutineContext,
) : CoroutineExecutor<ChatIntent, Unit, ChatState, ChatResult, ChatEffect>(executorContext) {

    override fun executeIntent(intent: ChatIntent, getState: () -> ChatState) {
        when (intent) {
            is ChatIntent.Send -> execute { send(intent.text) }
            is ChatIntent.Decide -> execute { decide(intent.requestId, intent.approve) }
            else -> Unit
        }
    }

    private suspend fun send(text: String) {
        val runtime = runtime.require(key)
        runCatching { repository.submit(key.profile, runtime, text) }
            .onSuccess { dispatch(ChatResult.Snapshot(project(getState().items))) }
            .onFailure { e -> if (e is CancellationException) throw e
                            else dispatch(ChatResult.Failed(e.toAppError())) }
    }
}
```

**规则**：
- Executor 内**不得**写 `try/catch(CancellationException)` —— `CoroutineExecutor` 的取消随
  `componentScope` 传播，吞掉就是 bug（现状 114 处样板，重写后应为 **0**）。
- 一次性事件只能通过 `publish(Effect)`，不得放进 State。

### 3.3 Store 工厂

```kotlin
internal class ChatStoreFactory(
    private val reducer: Reducer<ChatState, ChatResult>,
    private val executorFactory: (CoroutineContext) -> ChatExecutor,
    private val bootstrapper: ChatBootstrapper,

    override fun create(): Store<ChatIntent, ChatState, ChatEffect> =
        object : DefaultStore<ChatIntent, ChatState, ChatResult, ChatEffect>(
            initialState = ChatState(),
```

### 5.1 `SessionRuntimeStore` —— 8 个平行 Map → 1 个值对象

```kotlin
// component/chat/SessionRuntimeStore.kt
@Immutable
data class SessionRuntime(
    val runtimeId: String,
    val fence: Long,          // = generator + revision 合并
    val cwd: String?,
    val lastEventAt: Long,
    val dirty: Boolean,
)

class SessionRuntimeStore {
    private val _runtimes = MutableStateFlow<ImmutableMap<SessionKey, SessionRuntime>>(persistentMapOf())
    val runtimes: StateFlow<ImmutableMap<SessionKey, SessionRuntime>> = _runtimes.asStateFlow()

    // 反向索引：runtimeId → SessionKey，消灭 4 处 O(n) 反查（事件热路径）
    private val byRuntimeId = mutableMapOf<String, SessionKey>()

    fun require(key: SessionKey): SessionRuntime = _runtimes.value[key] ?: error("no runtime for $key")
    fun keyOf(runtimeId: String): SessionKey? = byRuntimeId[runtimeId]
    fun put(key: SessionKey, runtime: SessionRuntime) { /* 同步维护 byRuntimeId */ }
    fun remove(key: SessionKey) { /* 同步清理 */ }
    fun clear()  // profile 切换
}
```

### 8.2 单实例锁（阻塞项，必须先验）

`nucleusApplication` 自带单实例锁。我们的 `SingleInstance`（`CreateMutexW` + 事件）
有 `--silent` 激活语义，不能让它抢走。

**三步判定，按顺序做**：

1. 读 `nucleus.nucleus-application` 3.0 dev 的 `nucleusApplication` 源码，
   找是否有 `singleInstance = false` 之类的参数；
2. 若无开关：看它用什么名字的 mutex / 文件锁。**我们提前用同名句柄占位**，
   使其判定"已有实例"后直接返回（此时它是 no-op，我们的锁仍然生效）；
3. 两条都不行 → 在 `shell/singleinstance/` 下写一个 fork 补丁或本地替代入口，
   把 `nucleusApplication` 降级为纯窗口宿主（不调用它的 Application 级 API）。

**验不过就不要迁**（09 篇 §3 的可切割点）。此时 S6 整段推后，v0.6.0 只交付 S1–S5 + S8。
