## 2. 分层与边界（照抄即可执行的规则）

### 2.1 四条 import 规则

| # | 规则 | 理由 |
|---|---|---|
| R1 | `component/` 与 `domain/` **不得** import `androidx.compose.*` | Decompose 的核心承诺：业务逻辑可纯 JVM 单测 |
| R2 | `core/` 与 `domain/` **不得** import `dev.shinglem.hermes.{component,ui,shell}` | 依赖单向向下 |
| R3 | `ui/` **不得** import `dev.shinglem.hermes.data` | UI 只认识 Component 与 domain 模型 |
| R4 | `dev.nucleusframework.*` **只允许** 出现在 `shell/` | Nucleus 可替换，代价锁在一层 |

`R4` 的实测例外：`di/Modules.kt` 若需引用 `NucleusTray` 类型，允许 —— 架构测试放行
`shell/` 与 `di/` 两个前缀。

### 3.1 三件套文件形状

```kotlin
interface ChatComponent {

    val effects: Flow<ChatEffect>

class DefaultChatComponent(
    componentContext: ComponentContext,
    private val repository: ChatRepository,
    private val runtime: SessionRuntimeStore,
    private val key: SessionKey,

    private val store: ChatStore = instanceKeeper.getStore {
```

```kotlin
// component/<域>/store/<域>Reducer.kt —— 纯函数，无框架
internal class ChatReducer : Reducer<ChatState, ChatResult> {
    override fun ChatState.reduce(result: ChatResult): ChatState = when (result) {
        is ChatResult.Delta -> copy(streaming = streaming.appendAnswer(result.text))
        is ChatResult.Reasoning -> copy(streaming = streaming.appendReasoning(result.text))
        is ChatResult.ToolStarted -> copy(streaming = streaming.startTool(result.id, result.name))
        is ChatResult.ToolFinished -> copy(streaming = streaming.finishTool(result.id, result.ok))
        is ChatResult.Snapshot -> copy(items = result.items)
        is ChatResult.Failed -> copy(error = result.error.toNotice())
    }
}
```

### 3.2 Executor（唯一 place 做 suspend 与取消）

```kotlin
internal class ChatExecutor(
    private val repository: ChatRepository,
    private val runtime: SessionRuntimeStore,
    private val key: SessionKey,
    executorContext: CoroutineContext,
) : CoroutineExecutor<ChatIntent, Unit, ChatState, ChatResult, ChatEffect>(executorContext) {

    override fun executeIntent(intent: ChatIntent, getState: () -> ChatState) {
        when (intent) {
            is ChatIntent.Send -> execute { send(intent.text) }
            is ChatIntent.Decide -> execute { decide(intent.requestId, intent.approve) }
            else -> Unit
        }
    }

    private suspend fun send(text: String) {
        val runtime = runtime.require(key)
        runCatching { repository.submit(key.profile, runtime, text) }
            .onSuccess { dispatch(ChatResult.Snapshot(project(getState().items))) }
            .onFailure { e -> if (e is CancellationException) throw e
                            else dispatch(ChatResult.Failed(e.toAppError())) }
    }
}
```

**规则**：
- Executor 内**不得**写 `try/catch(CancellationException)` —— `CoroutineExecutor` 的取消随
  `componentScope` 传播，吞掉就是 bug（现状 114 处样板，重写后应为 **0**）。
- 一次性事件只能通过 `publish(Effect)`，不得放进 State。

### 3.3 Store 工厂

```kotlin
internal class ChatStoreFactory(
    private val reducer: Reducer<ChatState, ChatResult>,
    private val executorFactory: (CoroutineContext) -> ChatExecutor,
    private val bootstrapper: ChatBootstrapper,
) : StoreFactory {
    override fun create(): Store<ChatIntent, ChatState, ChatEffect> =
        object : DefaultStore<ChatIntent, ChatState, ChatResult, ChatEffect>(
            initialState = ChatState(),
            reducer = reducer,
            executorFactory = executorFactory,
            bootstrapper = bootstrapper,
        ) {}
}
```

### 8.2 单实例与 `--silent`（采用 Nucleus，见 ADR-066）

**结论**：`enableSingleInstance = true`（**静默也占锁**），
用 `DecoratedWindow(visible = !silent)` 控制首启不显示，用 `SingleInstanceManager.configuration`
按 `<home>` 隔离便携包。**删除**自研 `SingleInstance.kt`（250 行）+ `SingleInstanceTest.kt`（83 行）。

四条对照（初版判断有两条是错的，已复核）：

| 需求 | Nucleus 的 hook | 结论 |
|---|---|---|
| `--silent` 首启不显示窗口 | `DecoratedWindow(visible: Boolean = true)` **公开参数**，一路传到 `TaoWindow` | ✅ 做得到（初版误判为"做不到"） |
| 便携包按 `<home>` 隔离 | `SingleInstanceManager.configuration` 是 **`public var`**，可覆盖 `lockFilesDir` + `lockIdentifier` | ✅ 做得到（初版误判） |
| `--silent` 二次触发抢前台 | `ObserveSingleInstanceRestore` internal 且无条件挂 | ⚠️ 属实，但**场景不可达**：本机任务 XML 只有 `<LogonTrigger><Delay>PT20S</Delay>`，无重复触发器 |
| 唤醒失败给反馈 | Nucleus 静默 `exitProcess(0)` | ⚠️ 属实，**用户已明确接受** |

**关键前提**：静默实例必须正常占锁 —— `acquireSingleInstanceLock` 在 `nucleusApplication` 里
无条件执行（只受 `enableSingleInstance` 控制，与 `--silent` 无关）。这样才能"自启静默占锁 → 用户手动启动被判定为第二实例 → 拉出窗口"。

#### 8.2.1 第二实例退出开销：**不做优化**（2026-11-14 结论）

曾怀疑"第二实例要跑完整个启动流程才退出"是用户感知的"启动慢"，据此加过 `SingleInstanceProbe`
提前探测（73ms 退出）。**实测证明这不是用户遇到的问题**：用户说的是**首实例界面出来后网关连接要
十来秒**，而首实例的耗时全部在**冷启 daemon**上（见 [06 篇 §3.3](06-本地后端与双模式.md)），
与单实例判定毫无关系。

同时提前探测**绕过了 Nucleus 的判定路径**，风险实打实：

- 首实例拿到锁时 `onLockAcquired` 会用 `onRestoreRequest` 去 `watchForRestoreRequests()`，
  那是**唯一**能让"第二实例请求 → 拉出窗口"生效的地方；配套的
  `SingleInstanceRestoreBus.fire()` / `ObserveSingleInstanceRestore` 都是 `internal`，外部抄不全。
  实测踩过：传空 Lambda 提前判定，第二实例正常退出但最小化的窗口再也不动了。
- 探测与 Nucleus 必须用**同一个**锁文件，漏设 `configuration` 就会恒为 FIRST、优化静默失效。

**结论：已回退，不要再往这个方向优化。** 现在的形状就是最简的：

```kotlin
// shell/entry/DesktopEntry.kt —— 只设配置，判定全交给 nucleusApplication

// acquireSingleInstanceLock 在 nucleusApplication 内部执行，含 watcher 装配与 System.exit(0)
```

### 8.2.2 标题栏必须自己画（S6 实测，2026-11-13）

否则编译报 `NO_VALUE_FOR_PARAMETER`。

### 8.3 托盘：`DesktopTray`（Swing）→ `NucleusTray`

**保持对外形状不变**（`install()` / `dispose()` / `menu()`），只换实现：

```kotlin
// shell/tray/NucleusTray.kt
class NucleusTray(private val container: AppContainer) {
    fun install()      // composenativetray 的原生菜单（解决 CMP-1936 中文乱码）
    fun dispose()
    fun menu(): List<TrayMenuItem>   // 保留现有 data 类型，测试可断言
}
```

**必须保住**：点图标先走 `SystemNotifications.consumePendingAction()`（现有顺序），
再决定"显示主窗口 / 退出"。

### 8.4 通知浮窗：独立 `Window` → Tao popup

现状 `NotificationOverlay.kt` 用 `Window(...)` 建一个无边框窗口，靠 `workArea()` 定位。

**改法**：Tao 提供 popup host（`TaoPopupHost`）与 `HostedWindow`。优先用
`HostedWindow`（语义最接近"第二个顶层窗口"）；若不可用，用主窗口内的 overlay +
`WindowInsets` 计算右下角位置。

**判据**：最小化/托盘态仍能弹出（这是 `NotificationOverlay` 注释里写明的硬要求）。
